Chapter 7

Transactions & MVCC

Hiểu cách PostgreSQL đảm bảo tính nhất quán dữ liệu khi nhiều transaction cùng đọc và ghi trên một database.

Một transaction gom nhiều SQL operation thành một đơn vị xử lý duy nhất. PostgreSQL sử dụng MVCC để cho phép nhiều transaction hoạt động đồng thời mà vẫn hạn chế việc block không cần thiết giữa reader và writer.

NOTE Trong PostgreSQL, mỗi statement chạy trong một transaction. Nếu bạn không mở transaction thủ công, PostgreSQL sẽ chạy statement trong một transaction ngầm định.

ACID và transaction boundary

ACID mô tả bốn thuộc tính cơ bản của transaction: Atomicity, Consistency, Isolation và Durability. Khi một transaction thành công, toàn bộ thay đổi được commit; khi thất bại, thay đổi có thể được rollback về trạng thái hợp lệ trước đó.

SQL 
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
WARNING Không giữ transaction mở lâu hơn cần thiết. Long-running transaction có thể giữ snapshot cũ, ảnh hưởng VACUUM và làm tăng bloat.

MVCC hoạt động như thế nào?

Thay vì update row theo cách khiến reader phải đợi writer, PostgreSQL tạo row version mới. Transaction nhìn thấy version nào phụ thuộc vào snapshot và isolation level của nó.

Ví dụ đọc dữ liệu

SQL 
SELECT
  customer_id,
  COUNT(*) AS total_orders,
  SUM(total_amount) AS revenue
FROM orders
GROUP BY customer_id
ORDER BY revenue DESC;

Isolation Levels

PostgreSQL hỗ trợ các mức isolation như READ COMMITTED, REPEATABLE READ và SERIALIZABLE. Mỗi mức đưa ra trade-off khác nhau giữa consistency, concurrency và chi phí thực thi.

READ COMMITTEDMỗi statementỨng dụng CRUD thông thường
