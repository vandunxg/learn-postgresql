= Cài đặt extension

Thông thường, quy trình đưa một extension vào trạng thái hoạt động gồm một vài bước. Trước hết, bạn cần tìm hiểu nên dùng extension nào, version nào và extension tương thích với cluster của bạn đến mức nào. Sau khi xác định được extension cần dùng, bạn phải cài đặt extension đó vào cluster.

Việc cài đặt extension vào cluster thực sự có nghĩa là triển khai extension vào các thư mục của PostgreSQL, tức là di chuyển mọi file và thư viện liên quan đến extension vào shared directory của cluster để PostgreSQL có thể tìm thấy code cần thiết để chạy extension.

Cuối cùng, bạn cần tạo extension trong từng database cần dùng extension đó. Việc này tương đương với việc bật extension trong một database cụ thể.

Để minh họa cách sử dụng một extension, chúng ta sẽ cài đặt `orafce`, một extension cung cấp các function tương thích với Oracle. Mô tả toàn bộ extension không nằm trong phạm vi của phần này; chỉ cần biết rằng extension này cung cấp một tập hợp function, data type và các thành phần khác khiến PostgreSQL trông giống một Oracle database hơn, từ đó giúp migrate một ứng dụng dựa trên Oracle dễ dàng hơn.

Các tiểu mục sau mô tả từng bước cần thiết để đưa extension vào trạng thái hoạt động.

== Cài đặt extension thông qua pgxnclient

Thông thường, bước đầu tiên khi cài đặt một extension là tìm hiểu thông tin về extension đó, tức là tìm kiếm extension đó. Trong trường hợp này, chúng ta đã biết mình đang tìm extension nào, nhưng hãy dùng `pgxn` để tìm kiếm nó:

[quote]
____
Lưu ý rằng version của `oraface` thường xuyên thay đổi. 4.5.0 là version mới nhất tại thời điểm viết sách, nhưng có thể bạn sẽ thấy một số version mới hơn.

____
[source,console,role="transcript"]
....
$ pgxn search --ext orafce
orafce 4.5.0
    Oracle's compatibility functions and packages
....

.Command
[source,bash]
....
pgxn search --ext orafce
....

.Output
[source,output]
....
orafce 4.5.0
    Oracle's compatibility functions and packages
....


Command `search` sẽ tìm trong hệ sinh thái mọi extension khớp với tiêu chí tìm kiếm của chúng ta, trong trường hợp này là tên extension (`--ext`). Nhờ `pgxn`, giờ chúng ta biết cần cài đặt version 4.2.1 của `orafce`, đây là version ổn định mới nhất có sẵn tại thời điểm viết sách.

Sau khi quyết định extension cần dùng, bạn có thể chạy command `install` của `pgxn` để cài đặt. Quy trình này bao gồm tải xuống source tree, biên dịch source tree (nếu cần), đóng gói source tree rồi đặt gói đó vào shared directory của PostgreSQL cluster.

Bạn có thể theo dõi quá trình đang diễn ra ở mức độ rất chi tiết bằng option `--verbose`. Nếu đang dùng `pgxn` với một user khác với user vận hành cluster, bạn có thể dùng option `--sudo` để yêu cầu `pgxn` chuyển sang một user có đặc quyền khi cần:

[source,console,role="transcript"]
....
$ pgxn install orafce --verbose --sudo
....

.Command
[source,bash]
....
pgxn install orafce --verbose --sudo
....


[quote]
____
Docker image dùng cho chương này có một user hệ điều hành được phép sử dụng `sudo` mà không cần nhập mật khẩu. Đây không phải là lựa chọn tốt trong môi trường production, nhưng chúng ta dùng cách này để đơn giản hóa việc thử nghiệm các ví dụ trong chương.

____
== Cài đặt extension thủ công

`pgxnclient` là một công cụ tốt để tự động hóa việc cài đặt extension, nhưng bạn vẫn có những lựa chọn khác để bổ sung tính năng cho PostgreSQL. Một cách khác là tải extension xuống thủ công và thực hiện mọi bước cần thiết để cluster nhận biết các chức năng mới.

Điểm bắt đầu là website PGXN tại https://pgxn.org. Website này cho phép bạn tìm kiếm một extension cụ thể theo tên hoặc keyword. Sau khi mở website PGXN, bạn sẽ thấy một hộp văn bản để nhập keyword cần tìm; vì đã biết tên extension, chúng ta có thể chọn Extensions từ menu xổ xuống.

Giao diện web được hiển thị trong ảnh chụp màn hình dưới đây:

image::chapter-12-figure-12-1-000.jpg[Hình 12.1: Trang chính của website PGXN]

*Hình 12.1: Trang chính của website PGXN*

Kết quả tìm kiếm sẽ hiển thị như trong ảnh chụp màn hình dưới đây, cho phép chúng ta truy cập trang extension với toàn bộ thông tin và tài liệu về quy trình cài đặt:

image::chapter-12-figure-12-2-000.jpg[Hình 12.2: Trang kết quả tìm kiếm của PGXN]

*Hình 12.2: Trang kết quả tìm kiếm của PGXN*

Sau khi tìm thấy extension cần dùng, chúng ta có thể tải extension xuống bằng cách nhấp vào biểu tượng tải xuống trên trang, tương tự biểu tượng được hiển thị ở góc trên bên phải của ảnh chụp màn hình dưới đây. Kết quả là chúng ta sẽ tải xuống một file zip chứa mọi thứ liên quan đến extension:

image::chapter-12-figure-12-3-000.jpg[Hình 12.3: Trang tải xuống extension]

*Hình 12.3: Trang tải xuống extension*

Để tiếp tục, trước hết bạn phải giải nén tập tin nén đã tải xuống:

[source,console,role="transcript"]
....
$ unzip orafce-4.5.0.zip
....

.Command
[source,bash]
....
unzip orafce-4.5.0.zip
....


Bây giờ bạn có thể chuyển vào thư mục được tạo cho extension này và biên dịch extension (hệ thống cần có compiler và toàn bộ công cụ build source cần thiết đã được cài đặt):

[source,console,role="transcript"]
....
$ cd orafce-4.5.0
$ make
....

.Command
[source,bash]
....
cd orafce-4.5.0
make
....


[quote]
____
Bạn sẽ cần các PGXS Makefile để biên dịch một extension từ đầu. Thông thường, các Makefile này được cài đặt cùng development tools của PostgreSQL. Ví dụ, trên các bản phân phối Linux dựa trên Red Hat, bạn phải cài đặt package `postgresql16-dev`. Trong Docker image của chương này, mọi công cụ cần thiết để biên dịch và cài đặt extension đã được chuẩn bị sẵn.

____
Nếu biên dịch thành công, extension sẽ được tạo và sẵn sàng để đưa vào shared library directory của PostgreSQL. Để di chuyển các file của extension vào cluster, bạn cần quyền truy cập vào các thư mục database, chẳng hạn thông qua `sudo`:

[source,console,role="transcript"]
....
$ sudo make install
....

.Command
[source,bash]
....
sudo make install
....


Từ đây, bạn có thể dùng statement `CREATE EXTENSION` trong mọi database cần extension này.

== Sử dụng extension đã cài đặt

Sau khi extension đã được cài đặt, tức là đã được triển khai vào PostgreSQL cluster thủ công hoặc thông qua `pgxn`, bạn có thể tạo extension trong từng database cần extension này.

Extension `orafce` phải được tạo bởi superuser, vì vậy bạn cần kết nối tới database với tư cách administrator để thực thi statement `CREATE EXTENSION`:

[source,console,role="transcript"]
....
$ psql -U postgres forumdb
psql (16.0)
Type "help" for help.


forumdb=# CREATE EXTENSION orafce;
CREATE EXTENSION
....

....

== Xóa extension đã cài đặt

Có thể có lúc bạn không còn cần một extension và muốn xóa extension đó khỏi cluster. Xóa các extension không còn được sử dụng là một thói quen tốt vì việc này giữ cho cluster sạch và tránh phụ thuộc vào những object bạn thực sự không cần.
Nếu một database không còn cần extension và các thành phần liên quan, bạn có thể thực thi statement `DROP EXTENSION`, và extension sẽ biến mất khỏi database. Tất nhiên, nếu extension được cài đặt bởi một database superuser, bạn cũng cần thực thi statement này với tư cách superuser. Với ví dụ `orafce`, superuser có thể thực hiện như sau:

[source,console,role="transcript"]
....
   $ psql -U postgres forumdb
   psql (16.0)
   Type "help" for help.


   forumdb=# DROP EXTENSION orafce;
   DROP EXTENSION
....

.Command
[source,bash]
....
psql -U postgres forumdb
....

.SQL
[source,sql]
....
DROP EXTENSION orafce;
....

.Output
[source,output]
....
   psql (16.0)
   Type "help" for help.


   DROP EXTENSION
....


Như bạn có thể hình dung, khi kiểm tra danh sách extension, mục `orafce` không còn được hiển thị nữa và mọi tính năng, bao gồm table `DUAL`, đã biến mất:

[source,console,role="transcript"]
....
   forumdb=# \dx
   ù                     List of installed extensions
       Name    | Version |     Schema     |           Description
    ---------+---------+------------+------------------------------
   pg_stat_statements | 1.10          | public        | track planning and execution
   statistics of all SQL stat
   ements executed
   plpgsql                | 1.0       | pg_catalog | PL/pgSQL procedural language
   (2 rows)


   forumdb=# SELECT * FROM oracle.dual;
   ERROR:     relation "oracle.dual" does not exist
   LINE 1: SELECT * FROM oracle.dual;
....

.SQL
[source,sql]
....
\dx SELECT * FROM oracle.dual;
....

.Output
[source,output]
....
   ù                     List of installed extensions
       Name    | Version |     Schema     |           Description
    ---------+---------+------------+------------------------------
   pg_stat_statements | 1.10          | public        | track planning and execution
   statistics of all SQL stat
   ements executed
   plpgsql                | 1.0       | pg_catalog | PL/pgSQL procedural language
   (2 rows)


   ERROR:     relation "oracle.dual" does not exist
   LINE 1: SELECT * FROM oracle.dual;
....


Việc xóa một extension khỏi một database duy nhất không xóa extension đó khỏi các database khác, nơi bạn đã thực thi statement `CREATE EXTENSION` một cách tường minh. Việc này cũng không xóa các file và thư viện của extension khỏi shared directory của cluster.

Cách xóa (gỡ triển khai) extension khỏi cluster phụ thuộc vào cách bạn đã cài đặt extension vào cluster ngay từ đầu.

== Xóa extension bằng pgxnclient

Command `uninstall` của pgxn thực hiện chính xác hành động ngược lại với command `install`: nó xóa mọi file liên quan đến extension. Các tùy chọn dòng lệnh cũng giống nhau, vì vậy chúng ta có thể thực thi một command đơn giản như sau:

[source,console,role="transcript"]
....
   $ pgxn uninstall orafce --sudo --verbose
....

.Command
[source,bash]
....
pgxn uninstall orafce --sudo --verbose
....


Mọi file liên quan đến extension sẽ được xóa khỏi các thư mục chứa shared library của cluster. Vì vậy, extension sẽ biến mất vĩnh viễn; nếu cần cài đặt lại, bạn sẽ phải bắt đầu lại từ bước đầu tiên.

== Xóa extension đã được biên dịch thủ công

Để xóa một extension mà bạn đã biên dịch thủ công từ source, bạn lại cần dùng `make`, lần này với command `uninstall`, trong thư mục nơi bạn đã giải nén tập tin nén vừa tải xuống:

[source,console,role="transcript"]
....
   $ cd orafce-4.2.1
   $ sudo make uninstall
....

.Command
[source,bash]
....
cd orafce-4.2.1
sudo make uninstall
....


[quote]
____
Tránh dùng lẫn các công cụ khác nhau để quản lý extension. Nếu cài đặt extension qua pgxnclient, tốt hơn hết là xóa extension bằng chính client đó; ngược lại, nếu cài đặt extension từ source, hãy dùng cùng cách tiếp cận để xóa extension.

____
Tóm lại, bạn đã thấy cách xử lý một extension bằng PGXN client hoặc thủ công thông qua hạ tầng PGXN. Trong phần tiếp theo, bạn sẽ học cách build extension của riêng mình.
