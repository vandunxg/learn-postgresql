= Quản lý trigger trong PostgreSQL

Trong phần trước, chúng ta đã nói về rule. Trong phần này, chúng ta sẽ tìm hiểu trigger và cách sử dụng trigger. Trước hết, nếu đã hiểu rule thì việc hiểu trigger khá đơn giản: rule là một event handler đơn giản, còn trigger là một event handler phức tạp hơn. Cũng như rule, trigger có các record `NEW` và `OLD`, với cùng ý nghĩa. Trigger có thể xử lý các event `INSERT`/`DELETE`/`UPDATE` và `TRUNCATE`. Một điểm khác giữa rule và trigger là trigger có thể xử lý các event `INSERT`/`UPDATE`/`DELETE` và `TRUNCATE` trước hoặc sau khi chúng xảy ra. Trigger cũng hỗ trợ option `INSTEAD OF`, nhưng chỉ trên view.

Do đó, các event chúng ta có thể xử lý gồm:

* `BEFORE INSERT/UPDATE/DELETE/TRUNCATE`
* `AFTER INSERT/UPDATE/DELETE/TRUNCATE`
* `INSTEAD OF INSERT/UPDATE/DELETE`

Với rule, record `NEW` chỉ có thể tồn tại cho operation `INSERT`, record `NEW` và `OLD` cho operation `UPDATE`, còn record `OLD` cho operation `DELETE`. Hai mục đầu tiên trong danh sách cũng có thể áp dụng cho foreign table và table thông thường, còn mục thứ ba chỉ áp dụng cho view. Xem thêm tại https://www.postgresql.org/docs/current/sql-createtrigger.html.

Tiếp theo, chúng ta sẽ thực hiện những bước đầu tiên để sử dụng trigger và tìm hiểu cách đạt được các kết quả tương tự như khi dùng rule. Trigger cho phép chúng ta làm mọi việc rule có thể làm, và còn nhiều hơn thế.

Trước khi tiếp tục, cần ghi nhớ hai điều:

* Nếu trigger và rule cùng tồn tại trên cùng một event của một table, rule luôn được kích hoạt trước trigger.
* Nếu có nhiều trigger trên cùng một event của một table (ví dụ `BEFORE INSERT`), chúng được thực thi theo thứ tự bảng chữ cái.

Có một loại trigger khác gọi là event trigger; loại trigger này sẽ được trình bày trong phần *Event trigger*.

== Cú pháp trigger

Theo tài liệu chính thức, cú pháp định nghĩa trigger như sau:

[source,sql]
....
CREATE [ CONSTRAINT ] TRIGGER name { BEFORE | AFTER | INSTEAD OF } { event [ OR ... ] } ON table_name [ FROM referenced_table_name ] [ NOT DEFERRABLE | [ DEFERRABLE ] [ INITIALLY IMMEDIATE | INITIALLY DEFERRED ] ] [ REFERENCING { { OLD | NEW } TABLE [ AS ] transition_relation_name } [ ... ] ] [ FOR [ EACH ] { ROW | STATEMENT } ] [ WHEN (condition) ] EXECUTE { FUNCTION | PROCEDURE } function_name (arguments) WHERE event can be one of: INSERT UPDATE [ OF column_name [, ... ] ] DELETE TRUNCATE
....

Ở đây, chúng ta chỉ xem xét những phần được sử dụng nhiều nhất của cú pháp này; xem thêm tại https://www.PostgreSQL.org/docs/current/sql-createtrigger.html. Các điểm chính khi thực thi trigger là:

* Event cần xử lý, chẳng hạn `INSERT`, `DELETE` hoặc `UPDATE`.
* Thời điểm `TRIGGER` bắt đầu được thực thi (chẳng hạn `BEFORE INSERT`).
* Trigger gọi một function để thực hiện một thao tác.

Function được trigger gọi phải được định nghĩa theo một dạng cụ thể, như prototype sau:

[source,console,role="transcript"]
....
CREATE OR REPLACE FUNCTION function_name RETURNS trigger as
$$
DECLARE
\....
BEGIN


     RETURN
END;
$$
LANGUAGE 'plpgsql';
....

.Command
[source,bash]
....

$
$
....

.Output
[source,output]
....
DECLARE
\....
BEGIN


     RETURN
END;
LANGUAGE 'plpgsql';
....


Các function được trigger gọi không nhận input parameter và phải trả về data type `TRIGGER`; các function này nhận các giá trị từ record `NEW`/`OLD`. Dựa trên prototype trước đó, một định nghĩa `TRIGGER` cho event `BEFORE INSERT` có thể được định nghĩa như sau:

[source,sql]
....
CREATE TRIGGER trigger_name BEFORE INSERT ON table_name FOR EACH ROW EXECUTE PROCEDURE function_name.
....

Cũng có thể dùng cú pháp sau:

[source,sql]
....
CREATE TRIGGER trigger_name BEFORE INSERT ON table_name FOR EACH STATEMENT EXECUTE PROCEDURE function_name.
....

Sự khác nhau giữa `FOR EACH ROW` và `FOR EACH STATEMENT` là:

* Trigger được định nghĩa với `FOR EACH ROW` sẽ được thực thi cho từng row tham gia vào operation (ví dụ từng row được insert, update hoặc delete) và thỏa mãn condition của trigger.
* Trigger được định nghĩa với `FOR EACH STATEMENT` chỉ được thực thi một lần cho mỗi SQL statement thỏa mãn condition của trigger, bất kể operation liên quan đến bao nhiêu row.

Trong phần tiếp theo, chúng ta sẽ thử triển khai những gì đã làm với rule, lần này bằng trigger.

== Trigger trên `INSERT`

Trong phần này, chúng ta sẽ xem cách tạo các trigger đầu tiên:

. Hãy quay lại rule đã viết trong phần nói về tùy chọn *ALSO*; khi đó chúng ta đã viết rule sau:

[source,sql]
....
CREATE OR REPLACE rule r_tags1 AS ON INSERT to tags WHERE NEW.tag like 'a%' DO ALSO INSERT INTO new_a_tags (pk, tag, parent)VALUES (NEW.pk, NEW.tag, NEW. parent);
....

. Bây giờ hãy xem cách đạt cùng mục tiêu bằng trigger. Trước hết, hãy đưa môi trường về trạng thái ban đầu:

[source,console,role="transcript"]
....
   forumdb=> drop table if exists new_tags cascade;
   forumdb=> create table new_tags as select * from tags limit 0;
   forumdb=> truncate table new_a_tags;
....

.SQL
[source,sql]
....
DROP TABLE if EXISTS new_tags CASCADE;
CREATE TABLE new_tags AS SELECT * FROM tags LIMIT 0;
truncate TABLE new_a_tags;
....


. Bây giờ có thể tạo function mà trigger sẽ gọi:

[source,console,role="transcript"]
....
   forumdb=> CREATE OR REPLACE FUNCTION f_tags() RETURNS trigger as
   $$
   BEGIN
       IF lower(substring(NEW.tag from 1 for 1)) = 'a' THEN
    insert into new_a_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
       END IF;
       RETURN NEW;
   END;
   $$
   LANGUAGE 'plpgsql';
   CREATE FUNCTION
....

== Biến `TG_OP`

Theo tài liệu chính thức tại https://www.PostgreSQL.org/docs/current/plpgsql-trigger.html, PostgreSQL cho phép điều khiển trigger bằng các biến đặc biệt. Trong đó, chúng ta đã gặp hai biến `NEW` và `OLD`. Một biến đặc biệt khác, `TG_OP`, cho biết trigger được kích hoạt bởi event nào. Các giá trị có thể có của `TG_OP` là `INSERT`, `DELETE`, `UPDATE` và `TRUNCATE`.

== Trigger cho `UPDATE` / `DELETE`

Bây giờ hãy quay lại ví dụ đã dùng trong *Hình 8.1*. Mục tiêu là tạo một function duy nhất có thể xử lý các event `INSERT`, `DELETE` và `UPDATE`. Trước hết, hãy đưa môi trường về trạng thái ban đầu:

Function xử lý cả ba event sẽ là `fcopy_tags()`; trigger `tcopy_tags` sẽ gọi function này. Function `fcopy_tags()` dùng biến `TG_OP` để phân biệt các event `INSERT`, `UPDATE` và `DELETE`.

[source,console,role="transcript"]

   $$
   BEGIN
   IF TG_OP = 'INSERT' THEN
          IF lower(substring(NEW.tag from 1 for 1)) = 'a' THEN
              insert into new_a_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
          ELSIF lower(substring(NEW.tag from 1 for 1)) = 'b' THEN
              insert into new_b_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
          END IF;
          RETURN NEW;
   END IF;
   END;
   $$
   LANGUAGE 'plpgsql';
   CREATE FUNCTION
....

[source,console,role="transcript"]
....
   forumdb=> CREATE OR REPLACE FUNCTION fcopy_tags() RETURNS trigger as
   $$
   BEGIN
   IF TG_OP = 'INSERT' THEN
            IF lower(substring(NEW.tag from 1 for 1)) = 'a' THEN
                 insert into new_a_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
           ELSIF lower(substring(NEW.tag from 1 for 1)) = 'b' THEN
                 insert into new_b_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
           END IF;
           RETURN NEW;

           IF lower(substring(OLD.tag from 1 for 1)) = 'a' THEN
                 DELETE FROM new_a_tags WHERE pk = OLD.pk;
           ELSIF lower(substring(OLD.tag from 1 for 1)) = 'b' THEN
                 DELETE FROM new_b_tags WHERE pk = OLD.pk;

Như kết quả cho thấy, cách tiếp cận dùng trigger hoạt động. Trong phần này, chúng ta đã thấy cách sửa đổi các event thuộc Data Manipulation Level (DML) bằng rule và trigger.
