= CTE trong PostgreSQL kể từ version 12

Kể từ PostgreSQL 12, cách thực thi CTE đã thay đổi: hai tùy chọn mới được giới thiệu, đó là `MATERIALIZED` và `NOT MATERIALIZED`. Nếu muốn CTE materialize một result set tạm thời, chúng ta phải thêm keyword `materialized`:

[source,console,role="transcript"]
....
forumdb=> with posts_author_1 as materialized
 (select p.* from posts p
 inner join users u on p.author=u.pk
 where username='enrico_pirozzi')
select pk,title from posts_author_1;
 pk |             title
----+------------------------------
  3 | A view of   Data types in C++
(1 row)
....

.SQL
[source,sql]
....
WITH posts_author_1 AS MATERIALIZED
 (SELECT p.* FROM posts p
 inner JOIN users u ON p.author = u.pk
 WHERE username = 'enrico_pirozzi')
SELECT pk, title FROM posts_author_1;
....

.Output
[source,output]
....
 pk |             title
----+------------------------------
  3 | A view of   Data types in C++
(1 row)
....


Query này materialize một result set tạm thời, giống như cách PostgreSQL từng tự động materialize trong các version trước. Nếu viết query với tùy chọn `NOT MATERIALIZE`, PostgreSQL sẽ không materialize bất kỳ result set tạm thời nào:

[source,console,role="transcript"]
....
forumdb=> with posts_author_1 as not materialized
 (select p.* from posts p
 inner join users u on p.author=u.pk
 where username='enrico_pirozzi')
select pk,title from posts_author_1;
 pk |                  title
----+------------------------------
  3 | A view of     Data types in C++
(1 row)
....

.SQL
[source,sql]
....
WITH posts_author_1 AS NOT MATERIALIZED
 (SELECT p.* FROM posts p
 inner JOIN users u ON p.author = u.pk
 WHERE username = 'enrico_pirozzi')
SELECT pk, title FROM posts_author_1;
....

.Output
[source,output]
....
 pk |                  title
----+------------------------------
  3 | A view of     Data types in C++
(1 row)
....


Nếu không chỉ định tùy chọn nào, mặc định sẽ là `NOT MATERIALIZED`. Điều này có thể gây vấn đề khi migrate một database từ một minor version lên PostgreSQL 12, vì behavior của query planner có thể thay đổi và performance cũng có thể thay đổi.

Từ version 12, chúng ta phải thêm tùy chọn `MATERIALIZED` nếu muốn các query có behavior và performance giống như ở các version trước.

== CTE – các trường hợp sử dụng

Sau đây là một số ví dụ về CTE:

. Trước tiên, chúng ta sẽ tạo hai table mới:

** `t_posts`, chứa tất cả row hiện có trong table posts
** `delete_posts`, có cùng cấu trúc dữ liệu với table `posts`

[source,console,role="transcript"]
....
forumdb=> create temp table t_posts as select * from posts;
SELECT 3

forumdb=> create table delete_posts as select * from posts limit 0;
SELECT 0
....

.SQL
[source,sql]
....
CREATE TEMP TABLE t_posts AS SELECT * FROM posts;
CREATE TABLE delete_posts AS SELECT * FROM posts LIMIT 0;
....

.Output
[source,output]
....
SELECT 3

SELECT 0
....


Các giá trị ban đầu của hai table `t_posts` và `delete_posts` như sau:

. Bây giờ, giả sử chúng ta muốn xóa một số row khỏi table `posts` và đồng thời chèn tất cả row đã xóa khỏi table `t_posts` vào table `delete_posts`. Để đạt được mục tiêu này, chúng ta phải sử dụng CTE như sau:

[source,console,role="transcript"]
....
forumdb=> with del_posts as (
     delete from t_posts
    where category in (select pk from categories where title
='Database Discussions')
    returning *)
    insert into delete_posts select * from del_posts;
    INSERT 0 2
....

.SQL
[source,sql]
....
WITH del_posts AS (
     DELETE FROM t_posts
    WHERE category IN (SELECT pk FROM categories WHERE title
 = 'Database Discussions')
    RETURNING *)
    INSERT INTO delete_posts SELECT * FROM del_posts;
....

[source,output]

....

[source,console,role="transcript"]

forumdb=> with ins_posts as ( insert into inserted_posts select *

WITH ins_posts AS (INSERT INTO inserted_posts SELECT *

pk FROM ins_posts);

== Query đệ quy

Trong PostgreSQL, có thể tạo các query đệ quy. Query đệ quy được dùng trong graph database và nhiều trường hợp phổ biến, chẳng hạn như khi dùng query trên các table biểu diễn menu của website.

Recursive CTE giúp tạo query đệ quy trong PostgreSQL.

== Các recursive CTE

Một recursive CTE là một cấu trúc đặc biệt cho phép một auxiliary statement tham chiếu đến chính nó và do đó join chính nó với các kết quả đã được tính trước đó. Điều này đặc biệt hữu ích khi cần join một table với số lần chưa biết trước, thường là để “explode” một cấu trúc cây phẳng. Giải pháp truyền thống sẽ cần một cơ chế lặp nào đó, có lẽ thông qua một cursor lặp qua toàn bộ result set, mỗi lần xử lý một tuple. Tuy nhiên, với recursive CTE, chúng ta có thể sử dụng một cách tiếp cận sạch và đơn giản hơn nhiều. Một recursive CTE được tạo từ một auxiliary statement gồm các thành phần sau:

* Một non-recursive statement, đóng vai trò là bootstrap statement và được thực thi khi auxiliary term được đánh giá lần đầu.
* Một recursive statement, có thể tham chiếu đến bootstrap statement hoặc tham chiếu đến chính nó.

Hai phần này được nối với nhau bằng predicate `UNION`. Ví dụ, hãy chèn một row mới vào table `tag`, rồi kiểm tra dữ liệu:

[source,console,role="transcript"]
....
forumdb=>    insert into tags (tag,parent) values ('PostgreSQL',1);
INSERT 0 1

forumdb=>    select * from tags order by pk;
 pk |          tag         | parent
----+-------------------+--------
  1 | Database             |
  2 | Operating Systems |
  3 | PostgreSQL           |        1
(3 rows)
....

.SQL
[source,sql]
....
INSERT INTO tags (tag, parent)
VALUES ('PostgreSQL', 1);
SELECT *
FROM tags
ORDER BY pk;
....

.Output
[source,output]
....
INSERT 0 1

 pk |          tag         | parent
----+-------------------+--------
  1 | Database             |
  2 | Operating Systems |
  3 | PostgreSQL           |        1
(3 rows)
....


Bây giờ chúng ta muốn “explode” cấu trúc cây phẳng và lần theo quan hệ giữa parent và child thông qua column `parent` của table `tags`. Vì vậy, kết quả mong muốn có dạng như sau:

[source,output]
....
level   |            tag
-------+------------------------
     1 | Database
     1 | Operating Systems
     2 | Database -> PostgreSQL
....

Để đạt được mục tiêu này, chúng ta phải thực hiện như sau:

[source,console,role="transcript"]
....
forumdb=> WITH RECURSIVE tags_tree AS (
 -- non recursive statement
SELECT tag, pk, 1 AS level
FROM tags WHERE parent IS NULL
UNION
-- recursive statement
SELECT tt.tag|| ' -> ' || ct.tag, ct.pk
, tt.level + 1
FROM tags ct
JOIN tags_tree tt ON tt.pk = ct.parent
)
SELECT level,tag FROM tags_tree
order by level;
 level |                tag
-------+------------------------
       1 | Database
       1 | Operating Systems
       2 | Database -> PostgreSQL
(3 rows)
....

.SQL
[source,sql]
....
WITH RECURSIVE tags_tree AS (
 -- non recursive statement
SELECT tag, pk, 1 AS level
FROM tags WHERE parent IS NULL
UNION
-- recursive statement
SELECT tt.tag|| ' -> ' || ct.tag, ct.pk
, tt.level + 1
FROM tags ct
JOIN tags_tree tt ON tt.pk = ct.parent
)
SELECT level, tag FROM tags_tree
ORDER BY level;
....

.Output
[source,output]
....
 level |                tag
-------+------------------------
       1 | Database
       1 | Operating Systems
       2 | Database -> PostgreSQL
(3 rows)
....
