= Khám phá rule trong PostgreSQL

Như đã đề cập trước đó, rule là các event handler đơn giản. Ở cấp độ user, có thể quản lý mọi event thực hiện thao tác ghi như sau:

* `INSERT`
* `DELETE`
* `UPDATE`

Ý tưởng cốt lõi của rule là thay đổi luồng xử lý của một event. Khi event xảy ra và thỏa mãn một số điều kiện, chúng ta có thể thực hiện những việc sau:

* Không làm gì và hủy thao tác của event đó.
* Kích hoạt một event khác thay cho event mặc định.
* Kích hoạt một event khác cùng với event mặc định.

Vì vậy, với một thao tác ghi như `INSERT`, chúng ta có thể thực hiện một trong ba hành động sau:

* Hủy thao tác.
* Thực hiện một thao tác khác thay cho `INSERT`.
* Thực thi `INSERT` và thực hiện một thao tác khác trong cùng transaction.

== Tìm hiểu các biến OLD và NEW

Trước khi làm việc với rule rồi đến trigger, chúng ta cần hiểu khái niệm về các biến `OLD` và `NEW`.

Các biến `OLD` và `NEW` biểu diễn trạng thái của row trong table trước hoặc sau event. Các giá trị `OLD` và `NEW` là các cursor đại diện cho toàn bộ record. Để hiểu rõ hơn, hãy xét một thao tác `UPDATE`; trong trường hợp này, biến `OLD` chứa giá trị của record đã có trong table, còn biến `NEW` chứa giá trị mà record sẽ có trong table sau thao tác `UPDATE`.

Ví dụ, hãy xét table tags với các record sau:

[source,console,role="transcript"]
....
forumdb=> select * from tags;
 pk |            tag           | parent
----+-------------------+--------
  1 | Operating Systems |
  2 | Linux                    |        1
  3 | Ubuntu                   |        2
  [..]
....

.SQL
[source,sql]
....
SELECT *
FROM tags;
....

.Output
[source,output]
....
 pk |            tag           | parent
----+-------------------+--------
  1 | Operating Systems |
  2 | Linux                    |        1
  3 | Ubuntu                   |        2
  [..]
....


Giả sử chúng ta muốn đổi tag có `pk=3` từ Ubuntu thành Fedora bằng thao tác `UPDATE` sau:

[source,console,role="transcript"]
....
forumdb=> update tags set tag='Fedora' where pk=3;
UPDATE 1
....

.SQL
[source,sql]
....
UPDATE tags
SET
    tag = 'Fedora'
WHERE pk = 3;
....

.Output
[source,output]
....
UPDATE 1
....


Biến `OLD` sẽ có các giá trị sau:

[source,text]
....
                                  pk        tag        parent
                                  3        Ubuntu        1
....

Biến `NEW` sẽ có các giá trị sau:

[source,text]
....
                                  pk        tag        parent
                                  3        Fedora         1
....

Về mặt logic, trong một số thao tác, cả biến `OLD` và biến `NEW` đều có thể tồn tại, nhưng trong các thao tác khác thì chỉ một trong hai biến có thể tồn tại. Dưới đây là phần trình bày chi tiết hơn:

[source,text]
....
               Operation/Variable                 NEW                      OLD

                      INSERT                     present                  absent
                      DELETE                     absent                   present
                      UPDATE                     present                  present
....

Bây giờ mọi thứ đã rõ hơn, chúng ta có thể bắt đầu làm việc với các rule.

== Rule cho INSERT

Hãy bắt đầu bằng cú pháp của rule:

[source,sql]
....
CREATE [ OR REPLACE ] RULE name AS ON event TO TABLE [ WHERE condition ] DO [ ALSO | INSTEAD ] { NOTHING | command | (command;
command ...) }
....

Như có thể thấy, định nghĩa rule cực kỳ đơn giản. Khi sử dụng một rule, có ba tùy chọn:

* Tùy chọn ALSO
* Tùy chọn INSTEAD
* Tùy chọn INSTEAD NOTHING

== Tùy chọn ALSO

Giả sử chúng ta muốn sao chép vào table a_tag mọi record trong table tags có giá trị của column tag bắt đầu bằng chữ a:

. Trước hết, hãy tạo một table mới có tên là `O_tags`:

[source,console,role="transcript"]
....
   forumdb=> create table O_tags (
        pk integer not null primary key,
        tag text,
        parent integer);
   CREATE TABLE
....

.SQL
[source,sql]
....
CREATE TABLE O_tags (
    pk integer NOT NULL PRIMARY KEY,
    tag text,
    parent integer);
....

.Output
[source,output]
....
   CREATE TABLE
....


. Sau đó, hãy tạo rule mới như sau:

[source,console,role="transcript"]
....
   forumdb=> create or replace rule r_tags1
        as on INSERT to tags
        where NEW.tag ilike 'O%' DO ALSO
       insert into O_tags(pk,tag,parent)values (NEW.pk,NEW.tag,NEW.
   parent);
   CREATE RULE
....

[source,sql]

        AS ON INSERT to tags

   parent);

== Rule cho DELETE/UPDATE

Trong phần trước, chúng ta đã xem cách sử dụng rule với event INSERT. Trong phần này, chúng ta sẽ xem cách sử dụng rule với event DELETE và UPDATE.

Bây giờ chúng ta sẽ xem một ví dụ hoàn chỉnh về cách sử dụng rule, bắt đầu từ các khái niệm được mô tả ở trên.

Các bước để đạt mục tiêu này được mô tả như sau:

. Tạo một table có tên `new_tags` giống table `tags`; table này sẽ cung cấp một môi trường sạch để kiểm thử.
. Tạo hai table: một table có tên `new_a_tags` để sao chép mọi record có tag bắt đầu bằng chữ a, và một table có tên `new_b_tags` để sao chép mọi record có tag bắt đầu bằng chữ b.
. Tạo các rule cần thiết cho INSERT, DELETE và UPDATE.

Hãy bắt đầu.

== Quản lý rule cho các event INSERT, DELETE và UPDATE

Mục tiêu này được minh họa trong hình sau:

*Hình 8.1: Quản lý rule*

Sơ đồ cho thấy table `new_tags` (`pk` là primary key kiểu `integer`, `tag` kiểu `text`, `parent` kiểu `integer`) được nối với `new_b_tags` bằng nhãn "COPY HERE ALL TAGS STARTING WITH 'b'", và được nối với `new_a_tags` bằng nhãn "COPY HERE ALL TAGS STARTING WITH 'a'". Hai table đích cũng có `pk` là primary key và các column `tag`, `parent` như table `new_tags`.

Chúng ta muốn mọi tag bắt đầu bằng chữ a được lưu trong table `new_tags` và đồng thời được sao chép vào table `new_a_tags`; các tag bắt đầu bằng chữ b cũng tương tự.

Chúng ta phải quản lý rule cho các event INSERT, DELETE và UPDATE theo các cách sau:

* Rule INSERT phải nhận diện mọi tag bắt đầu bằng chữ a hoặc b và sao chép các record đó vào table tương ứng, `new_a_tags` và `new_b_tags`.
* Rule DELETE phải nhận diện mọi tag bắt đầu bằng chữ a hoặc b và xóa các record đó khỏi table tương ứng, `new_a_tags` và `new_b_tags`.
* Rule UPDATE phải nhận diện mọi tag bắt đầu bằng chữ a hoặc b; nếu tag của một record thay đổi, rule phải kiểm tra xem record đó cần được sao chép vào hay xóa khỏi các table `new_a_tags` và `new_b_tags`.

== Rule cho DELETE

Bây giờ hãy tạo các rule DELETE. Cần tạo rule để khi một record có tag bắt đầu bằng chữ a hoặc b bị xóa khỏi table `new_tags`, bản sao của nó trong table `new_a_tags` hoặc `new_b_tags` cũng bị xóa. Với mọi record có tag bắt đầu bằng chữ a, chúng ta cần rule sau:

[source,console,role="transcript"]

forumdb=> create or replace rule r_new_tags_delete_a as on delete to new_
tags where OLD.tag like 'a%' DO ALSO delete from new_a_tags where pk=OLD.
pk;
CREATE RULE
....

== Rule cho UPDATE

Bây giờ chúng ta cần tạo một rule để kiểm tra xem tag có được cập nhật thành một từ bắt đầu bằng a hoặc b hay không. Cách đơn giản là trước tiên tạo một function thực hiện việc kiểm tra này, rồi tạo một rule dựa trên function đó. Hãy bắt đầu bằng cách tạo function:

[source,console,role="transcript"]
....
forumdb=> create or replace function move_record (p_pk integer, p_tag
text, p_parent integer,p_old_pk integer,p_old_tag text ) returns void
language plpgsql as
$$
BEGIN
     if left(lower(p_tag),1) in ('a','b') THEN
           delete from new_tags where pk = p_old_pk;
           insert into new_tags values(p_pk,p_tag,p_parent);
   end if;
END;
$$;
CREATE FUNCTION
....

[source,bash]
....
$
$;
....

.SQL
[source,sql]
....

text, p_parent integer, p_old_pk integer, p_old_tag text)
    returns void

....
