= Triển khai auditing

Auditing cho phép thực hiện introspection đối với một application hoặc user session; nói cách khác, có thể tái tạo từng bước những gì user hoặc application yêu cầu database cluster thực hiện.

Auditing hơi khác logging, vì logging chỉ cung cấp một cách đơn giản để ghi lại các action của user, chứ không giúp dễ dàng reconstruct interaction giữa user hoặc application với database cluster. Trên thực tế, trong một database cluster có concurrency cao, các action do nhiều user khác nhau thực hiện có thể cùng xuất hiện trong log dưới dạng các dòng đan xen. Hơn nữa, logging không cho biết rõ nó đang ghi lại điều gì, nên sẽ khó xác định user đã làm gì. Điều này càng đúng khi user hoặc application thực thi các statement phức tạp, đặc biệt là những statement không hiển thị rõ parameter và value.

Ví dụ, hãy xem phần đơn giản sau:

[source,console,role="transcript"]
....
   forumdb=> PREPARE my_query( text ) AS SELECT * FROM forum.categories WHERE
   title like $1;
   PREPARE
   forumdb=>     EXECUTE my_query( 'PROGRAMMING%' );
      pk |           title             |              description
   ----+-----------------------+---------------------------------
      3 | PROGRAMMING LANGUAGES | All about programming languages
   (1 row)
....

.SQL
[source,sql]
....
PREPARE my_query(text) AS SELECT * FROM forum.categories WHERE
   title like $1;
EXECUTE my_query('PROGRAMMING%');
....

.Output
[source,output]
....
   PREPARE
      pk |           title             |              description
   ----+-----------------------+---------------------------------
      3 | PROGRAMMING LANGUAGES | All about programming languages
   (1 row)
....


Khi bật verbose logging, phần này sẽ cho ra output sau:

[source,text]
....
   LOG: duration: 19.011 ms statement: PREPARE my_query( text ) AS SELECT *
   FROM forum.categories WHERE title like $1;
   LOG:      duration: 6.539 ms    statement: EXECUTE my_query( 'PROGRAMMING%' );
....

Như bạn thấy, log chứa mọi thông tin cần thiết để reconstruct những gì user đã làm, nhưng việc này không đơn giản. Bạn phải nhận ra rằng hai dòng có liên quan với nhau và session thực thi các statement đó là cùng một session. Điều này không phải lúc nào cũng khả thi, đặc biệt khi có các query khác được ghi log ở giữa hai dòng bạn quan tâm.

Ngoài ra, log có thể không báo cáo toàn bộ thông tin bạn cần, chẳng hạn vì bạn đã chọn không ghi các statement có thời gian thực thi ngắn hơn một threshold.

Vì vậy, mặc dù có thể dùng logging để thực hiện auditing, đó không phải lúc nào cũng là lựa chọn tốt nhất. Trong section này, bạn sẽ tìm hiểu về extension PgAudit, được tạo ra nhằm cung cấp một auditing infrastructure đáng tin cậy và dễ sử dụng. PgAudit tận dụng logging facility mạnh mẽ của PostgreSQL; do đó, bạn cần cấu hình logging infrastructure phù hợp, như sẽ thấy trong các subsection tiếp theo.

Trước khi đi vào cấu hình và cách sử dụng PgAudit, có một số chi tiết và khái niệm cần được giải thích. PgAudit có thể hoạt động theo hai cách khác nhau: auditing theo session hoặc theo object. Cách đầu tiên là cách nhanh và đơn giản để audit một phần (hoặc toàn bộ) session của user hay application; cách thứ hai phức tạp và chi tiết hơn, dùng để log các action liên quan đến những database object cụ thể (ví dụ: ai đã delete row khỏi table đó?).

Auditing theo session hoạt động bằng cách cấu hình các category của statement cần audit trong một session. Ngược lại, auditing theo object yêu cầu cấu hình từng database role; tùy vào tập permission được cấp, các role đó sẽ kích hoạt audit cho những action cụ thể. Trong các subsection tiếp theo, bạn sẽ thấy cả hai cách này được dùng để audit.

== Cài đặt PgAudit

Cách nhanh nhất để cài đặt PgAudit là sử dụng package manager của operating system. Ví dụ, trên hệ thống GNU/Debian hoặc Ubuntu, bạn có thể nhập:

[source,console,role="transcript"]
....
   $ sudo apt install pgaudit-16-pgaudit
....

.Command
[source,bash]
....
sudo apt install pgaudit-16-pgaudit
....


Nếu cần cài đặt PgAudit từ source, trước tiên bạn phải tải về một version tương thích với PostgreSQL cluster của mình, sau đó giải nén và cài đặt:

[source,console,role="transcript"]
....
   $ wget https://github.com/pgaudit/pgaudit/archive/refs/tags/1.7.0.tar.gz
   ..
   $ tar xzvf 1.7.0.tar.gz
   ...
   $ cd pgaudit-1.7.0
   $ make USE_PGXS=1
   ...

   $ sudo make USE_PGXS=1 install
....

.Command
[source,bash]
....
wget https://github.com/pgaudit/pgaudit/archive/refs/tags/1.7.0.tar.gz
tar xzvf 1.7.0.tar.gz
cd pgaudit-1.7.0
make USE_PGXS=1
sudo make USE_PGXS=1 install
....

.Output
[source,output]
....
   ..
   ...
   ...
....


Sau khi cài đặt extension, bạn phải cấu hình PostgreSQL để sử dụng PgAudit.

== Cấu hình PostgreSQL để sử dụng PgAudit

PgAudit là một extension phải được load khi server startup. Vì vậy, bạn phải sửa configuration file chính, `postgresql.conf`, để thêm library `pgaudit` như sau:

[source,text]
....
   shared_preload_libraries = 'pgaudit'
....

Tiếp theo, hãy restart cluster để các thay đổi có hiệu lực:

[source,console,role="transcript"]
....
   $    pg_ctl -D /postgres/16/data restart
....

.Command
[source,bash]
....
   pg_ctl -D /postgres/16/data restart
....


Vì PgAudit là một extension, bạn phải enable nó trong database mà mình muốn audit. Để đơn giản, hãy enable nó trong database `forumdb` của chúng ta (bạn cần connect với tư cách database superuser):

[source,console,role="transcript"]
....
   forumdb=# CREATE EXTENSION pgaudit;
   CREATE EXTENSION
....

.SQL
[source,sql]
....
CREATE EXTENSION pgaudit;
....

.Output
[source,output]
....
   CREATE EXTENSION
....


Bây giờ cần quyết định khi nào và bằng cách nào áp dụng auditing.

[quote]
____
Nếu đang sử dụng Docker image cho chương này, PgAudit đã được cài đặt sẵn cho bạn!

____
== Cấu hình PgAudit

PgAudit đi kèm một tập hợp phong phú các configuration parameter, cho phép bạn chỉ định chính xác nội dung nào cần log, khi nào log, những gì cần loại trừ khỏi auditing, v.v. Tất cả configuration parameter đều nằm trong namespace `pgaudit` để không xung đột với các setting hiện có khác cùng tên.

Setting quan trọng nhất là `pgaudit.log`, xác định các statement và action bạn muốn audit. Parameter này có thể nhận bất kỳ value nào sau đây:

* `ALL` để audit mọi statement
* `NONE` để không audit bất kỳ thứ gì
* `READ` để chỉ audit các statement `SELECT` và `COPY`
* `WRITE` để audit mọi statement sửa đổi dữ liệu (`INSERT`, `UPDATE` và `COPY`)
* `ROLE` để audit việc thay đổi hoặc tạo role
* `DDL` để audit mọi data-definition statement, và do đó mọi thay đổi đối với cấu trúc database
* `FUNCTION` để audit mọi lần thực thi code, bao gồm cả các DO block
* `MISC` để audit mọi value chưa được phân loại rõ ràng ở trên
* `MISC_SET` để audit mọi command kiểu SET

Bạn có thể chỉ định nhiều setting cùng lúc bằng cách phân tách các tên bằng dấu phẩy, ví dụ:

[source,text]
....
   pgaudit.log = 'WRITE,FUNCTION';
....

Chức năng này có thể được dùng để audit mọi thay đổi dữ liệu và mọi lần thực thi code.

Một configuration parameter quan trọng khác là `pgaudit.log_level`, chỉ định log level mà PgAudit dùng để ghi các audit message vào log. Theo mặc định, setting này nhận value `log`, nhưng bạn có thể đổi thành bất kỳ log threshold nào khác, ngoại trừ các threshold dành cho error (chẳng hạn `ERROR`, `FATAL` và `PANIC`).

Để bổ sung chi tiết vào audit information, có lẽ bạn sẽ muốn enable parameter `pgaudit.log_parameter` để dump mọi query parameter (bạn sẽ thấy một ví dụ ở phần sau).

Nếu định cấu hình PgAudit theo object, bạn cần set parameter `pgaudit.role`, như sẽ thấy ở phần sau của chương này.
== Auditing theo session

Cách đầu tiên để sử dụng PgAudit (và cũng là cách dễ hiểu, dễ thử nhất) là audit theo session.

Cũng như các setting cấu hình khác, bạn có thể thiết lập cấu hình của PgAudit thông qua `SET` SQL statement. Cách này hữu ích để test cấu hình trước khi áp dụng cho toàn bộ cluster. Hãy thử thiết lập `pgaudit.log` trực tiếp trong một interactive session rồi thực hiện vài action để xem điều gì xảy ra. Ví dụ, giả sử chúng ta muốn audit mọi thay đổi đối với dữ liệu:

[source,console,role="transcript"]
....
   forumdb=# SET pgaudit.log TO 'write, ddl';
   SET
   forumdb=# SELECT count(*) FROM forum.categories;
      count
   -------
          3
   (1 row)


   forumdb=# INSERT INTO forum.categories( description, title ) VALUES(
   'Fake', 'A Malicious Category' );
   INSERT 0 1


   forumdb=# SELECT count(*) FROM forum.categories;
      count
   -------
          4
   (1 row)


   forumdb=# INSERT INTO forum.categories( description, title ) VALUES(
   'Fake2', 'Another Malicious Category' );
   INSERT 0 1
....

.SQL
[source,sql]
....
SET pgaudit.log TO 'write, ddl';
SELECT count(*)
FROM forum.categories;
INSERT INTO forum.categories (description, title)
VALUES ('Fake', 'A Malicious Category');
SELECT count(*)
FROM forum.categories;
INSERT INTO forum.categories (description, title)
VALUES ('Fake2', 'Another Malicious Category');
....

.Output
[source,output]
....
   SET
      count
   -------
          3
   (1 row)


   INSERT 0 1


      count
   -------
          4
   (1 row)


   INSERT 0 1
....


`pgaudit.log` chỉ có thể được set bởi superuser. Vì vậy, nếu muốn thử dynamic setting này trong một interactive session, bạn cần connect với tư cách database administrator. Tất nhiên, bạn có thể đặt parameter này cho tất cả user ở cluster-wide level bằng cách đặt parameter trong configuration file `postgresql.conf`.

Trong log, PostgreSQL sẽ ghi nội dung tương tự như sau:

[source,text]
....
   LOG: AUDIT: SESSION,1,1,WRITE,INSERT,,,"INSERT INTO forum.categories(
   description, title ) VALUES( 'Fake', 'A Malicious Category' );",<not
   logged>
   LOG: AUDIT: SESSION,2,1,WRITE,INSERT,,,"INSERT INTO forum.categories(
   description, title ) VALUES( 'Fake2', 'Another Malicious Category'
   );",<not logged>
....

Một dòng log như vậy chứa nhiều chi tiết, nhưng trước khi xem xét các field, hãy lưu ý rằng không có gì được ghi về hai câu lệnh `SELECT`: vì chúng ta yêu cầu PgAudit không audit các query `READ`, các câu lệnh `SELECT` đã bị loại khỏi quá trình audit.

Hãy lưu ý rằng mọi dòng audit đều có prefix dễ nhận biết là `AUDIT`, nhờ đó bạn có thể dễ dàng biết dòng log đó do PgAudit tạo ra hay do một event nội bộ khác của PostgreSQL.

Mỗi dòng cho biết audit type (trong ví dụ trước là `SESSION`) và một counter tăng dần, biểu thị thứ tự thời gian của các statement được audit. Tiếp theo là category của statement mà PgAudit nhận diện (trong ví dụ trước, cả hai đều là event `WRITE`), rồi đến các statement hoàn chỉnh đã được thực thi. Còn một số chi tiết khác sẽ được thảo luận trong các ví dụ tiếp theo.

Hãy xem một ví dụ khác: thực thi một query được xây dựng động như sau:

[source,console,role="transcript"]
....
   forumdb=# DO $$ BEGIN
   EXECUTE 'TRUNCATE TABLE ' || 'forum.tags CASCADE';
   END $$;
   NOTICE:    truncate cascades to table "forum.j_posts_tags"
   DO
....

.SQL
[source,sql]
....
DO $$ BEGIN
   EXECUTE 'TRUNCATE TABLE ' || 'forum.tags CASCADE';
....

.Output
[source,output]
....
   END $$;
   NOTICE:    truncate cascades to table "forum.j_posts_tags"
   DO
....


Thay vì thực thi statement `TRUNCATE TABLE tags`, statement này được tạo bằng cách nối hai string. Trong log, PgAudit ghi một dòng như sau:

[source,text]
....
   LOG: AUDIT: SESSION,3,1,WRITE,TRUNCATE TABLE,,,TRUNCATE TABLE forum.tags
   CASCADE,<not logged>
....

Một lần nữa, dòng này báo cáo auditing mode (`SESSION`), số thứ tự của statement được audit (`3`), category (`WRITE`) và statement (`TRUNCATE TABLE`), cũng như statement hoàn chỉnh đã được thực thi. Chi tiết cuối cùng này rất quan trọng: nếu bạn thực thi cùng statement mà không audit, PostgreSQL log sẽ chứa một dòng như sau:

[source,text]
....
   LOG:    duration: 12.616 ms        statement: DO $$ BEGIN
             EXECUTE 'TRUNCATE TABLE ' || 'forum.tags CASCADE';
             END $$;
....

Ở đây, bạn có thể thấy log đã sao chép nguyên xi source statement, bao gồm cả string concatenation và newline, khiến statement khó đọc và khó search hơn.

== Auditing theo role

Cơ chế audit theo role của PgAudit cho phép bạn xác định rất chi tiết những event mình quan tâm.

Ý tưởng là bạn định nghĩa một database role rồi grant cho role đó các permission tương ứng với những action muốn audit. Sau khi role và các permission của nó được thiết lập, bạn cho PgAudit biết phải audit theo role đó. Khi ấy, PgAudit sẽ báo cáo trong log mọi action khớp với các permission đã được grant cho auditing role, bất kể role nào đã thực hiện action đó.

Vì vậy, bước đầu tiên là tạo một role chỉ dùng để chỉ định những action cần audit và không được dùng như một role thông thường cho các interactive session:

[source,console,role="transcript"]
....
   forumdb=# CREATE ROLE auditor WITH NOLOGIN;
   CREATE ROLE
....

.SQL
[source,sql]
....
CREATE ROLE auditor WITH NOLOGIN;
....

.Output
[source,output]
....
   CREATE ROLE
....


Để chỉ định những action mà role phải audit, chúng ta chỉ cần `GRANT` các permission tương ứng cho role. Ví dụ, giả sử chúng ta muốn audit mọi action `DELETE` trên mọi table và chỉ audit action `INSERT` trên `posts` và `categories`, chúng ta phải grant cho role tập permission sau:

[source,console,role="transcript"]
....
   forumdb=# GRANT DELETE ON ALL TABLES IN SCHEMA forum TO auditor;
   GRANT
   forumdb=# GRANT INSERT ON forum.posts TO auditor;
   GRANT
   forumdb=# GRANT INSERT ON forum.categories TO auditor;
   GRANT
....

.SQL
[source,sql]
....
GRANT DELETE ON ALL TABLES IN SCHEMA forum TO auditor;
GRANT INSERT ON forum.posts TO auditor;
GRANT INSERT ON forum.categories TO auditor;
....

.Output
[source,output]
....
   GRANT
   GRANT
   GRANT
....


Mọi thứ đã sẵn sàng để PgAudit hoạt động, nhưng auditing system vẫn cần biết phải sử dụng role `auditor`. Vì vậy, chúng ta cần configure `pgaudit.role` trong cluster configuration hoặc trong current session. Cách thứ nhất dĩ nhiên phù hợp để dùng trong production environment, còn set configuration parameter trong một session riêng lẻ hữu ích cho mục đích test. Hãy set parameter trong session với tư cách database administrator để thử hoạt động của nó:

[source,console,role="transcript"]
....
   forumdb=# SET pgaudit.role TO auditor;
   SET
....

.SQL
[source,sql]
....
SET pgaudit.role TO auditor;
....

.Output
[source,output]
....
   SET
....


Bây giờ hãy thực thi một vài statement và xem PgAudit ghi gì vào cluster log:

[source,console,role="transcript"]
....
   forumdb=# INSERT INTO forum.categories( title, description ) VALUES(
   'PgAudit', 'Topics related to auditing in PostgreSQL' );
   INSERT 0 1


   -- this will not be logged
   forumdb=# INSERT INTO forum.tags( tag ) VALUES( 'pgaudit' );
   INSERT 0 1


   forumdb=# DELETE FROM forum.posts WHERE author NOT IN ( SELECT pk FROM
   forum.users WHERE username NOT IN ( 'fluca1978', 'sscotty71' ) );
   DELETE
....

.SQL
[source,sql]
....
INSERT INTO forum.categories (title, description)
VALUES ('PgAudit', 'Topics related to auditing in PostgreSQL');
INSERT INTO forum.tags (tag)
VALUES ('pgaudit');
DELETE FROM forum.posts WHERE author NOT IN (SELECT pk FROM
   forum.users WHERE username NOT IN ('fluca1978', 'sscotty71'));
....

.Output
[source,output]
....
   INSERT 0 1


   -- this will not be logged
   INSERT 0 1


   DELETE
....


Như bạn có thể hình dung, PgAudit sẽ log statement đầu tiên và cuối cùng trong session ở ví dụ trên; thực tế, chỉ hai statement đó liên quan đến các table và action tương ứng với những permission đã được grant cho auditing role.

Trong PostgreSQL log, bạn sẽ tìm thấy các dòng tương tự như sau:

[source,text]
....
   LOG: AUDIT: OBJECT,1,1,WRITE,INSERT,TABLE,forum.categories,"INSERT INTO
   forum.categories( title, description ) VALUES( 'PgAudit', 'Topics related
   to auditing in PostgreSQL' );",<not logged>
   LOG: AUDIT: OBJECT,2,1,WRITE,DELETE,TABLE,forum.posts,"DELETE FROM forum.
   posts WHERE author NOT IN ( SELECT pk FROM forum.users WHERE username NOT
   IN ( 'fluca1978', 'sscotty71' ) );",<not logged>
....

Hãy lưu ý rằng tuple insertion vào table `tags` không xuất hiện: tuple này không được audit hay log vì auditing role không có permission cụ thể được `GRANT` trên table đó.

Sau khi auditing role đã được configure đúng, chúng ta có thể lưu cấu hình bằng cách sửa configuration file `postgresql.conf` và set tunable `pgaudit.role` như sau:

[source,text]
....
      pgaudit.role = 'auditor'
....

Như bạn có thể thấy, auditing theo role linh hoạt hơn nhiều so với auditing theo session: auditing theo session chỉ cho phép bạn chỉ định category của các action cần audit, còn auditing theo role cho phép xác định chính xác những statement nào cần audit.
