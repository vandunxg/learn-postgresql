= Khám phá function và language

PostgreSQL có khả năng thực thi code ở phía server. Có nhiều cách để cung cấp cho PostgreSQL đoạn code cần thực thi. Ví dụ, người dùng có thể tạo function bằng nhiều ngôn ngữ lập trình khác nhau. Các language chính mà PostgreSQL hỗ trợ gồm:

* SQL
* PL/pgSQL
* C

Các language được liệt kê ở trên là built-in language; ngoài ra, PostgreSQL còn có thể quản lý những language khác, nhưng trước khi sử dụng, chúng ta cần cài đặt chúng trên hệ thống. Một số language khác được hỗ trợ gồm:

* PL/Python
* PL/Perl
* PL/tcl
* PL/Java

Trong phần này, chúng ta sẽ tìm hiểu về SQL function và PL/pgSQL.

== Function

Cú pháp của command dùng để định nghĩa một function như sau:

[source,sql]
....
CREATE FUNCTION function_name(p1 type, p2 type, p3 type, ....., pn type)
    RETURNS type AS
BEGIN
    -- function logic
END;
LANGUAGE language_name
....

Các bước sau luôn áp dụng cho mọi loại function mà chúng ta muốn tạo:

. Chỉ định tên function sau các keyword `CREATE FUNCTION`.
. Lập danh sách các parameter, phân tách bằng dấu phẩy.
. Chỉ định return data type sau keyword `RETURNS`.
. Với language PL/pgSQL, đặt code giữa block `BEGIN` và `END`.
. Với language PL/pgSQL, function phải kết thúc bằng keyword `END`, theo sau là dấu chấm phẩy.
. Xác định language dùng để viết function, chẳng hạn sql, plpgsql, plperl, plpython, v.v.

Đây là cấu trúc cơ bản mà chúng ta sẽ dùng làm tham chiếu trong phần còn lại của chương; trong một số trường hợp cụ thể, cấu trúc này có thể có một vài biến thể nhỏ.

== SQL function

SQL function là cách đơn giản nhất để viết function trong PostgreSQL; bên trong function, chúng ta có thể sử dụng bất kỳ SQL command nào.

== Function cơ bản

Phần này trình bày những bước đầu tiên với SQL function. Ví dụ, function sau thực hiện phép cộng hai số:

[source,console,role="transcript"]
....
forumdb=> CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS
integer AS $$
   SELECT x + y;
$$ LANGUAGE SQL;
CREATE FUNCTION



forumdb=> select my_sum(1,2);
   my_sum
--------
        3
(1 row)
....

.Command
[source,bash]
....
$ LANGUAGE SQL;
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION my_sum(x integer, y integer)
    RETURNS
integer AS $$
   SELECT x + y;
select my_sum(1,2);
....

.Output
[source,output]
....
CREATE FUNCTION



   my_sum
--------
        3
(1 row)
....


Như trong ví dụ trước, code của function được đặt giữa `$$`; có thể xem `$$` là các label. Có thể gọi function bằng statement `SELECT` mà không cần clause `FROM`. Các argument của SQL function có thể được tham chiếu trong function body bằng số (cách cũ) hoặc bằng tên (cách mới). Ví dụ, có thể viết function tương tự như sau:

[source,console,role="transcript"]
....
CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS integer AS $$
 SELECT $1 + $2;
$$ LANGUAGE SQL;
....

.Command
[source,bash]
....
CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS integer AS $$
 SELECT $1 + $2;
$ LANGUAGE SQL;
....


Trong function trên, chúng ta thấy cách cũ để tham chiếu parameter bên trong function. Theo cách này, parameter được tham chiếu theo vị trí: giá trị `$1` tương ứng với parameter thứ nhất, `$2` tương ứng với parameter thứ hai, v.v. Trong code của SQL function, chúng ta có thể sử dụng mọi SQL command, bao gồm các command đã thấy trong những chương trước.

== SQL function trả về một result set

Trong phần này, chúng ta sẽ xem cách tạo một SQL function trả về một result set gồm các giá trị của một data type. Ví dụ, giả sử muốn viết một function nhận `p_title` làm parameter, xóa mọi row có `title=p_title`, đồng thời trả về tất cả key của các row đã xóa. Function sau thực hiện việc đó:

[source,console,role="transcript"]
....
forumdb=> CREATE OR REPLACE FUNCTION delete_posts(p_title text) returns
setof integer as $$
delete from posts where title=p_title returning pk;
$$
LANGUAGE SQL;
CREATE FUNCTION
....

.Command
[source,bash]
....
$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION delete_posts(p_title text)
    returns
setof integer AS $$
delete from posts where title=p_title returning pk;
....

.Output
[source,output]
....
LANGUAGE SQL;
CREATE FUNCTION
....


Đây là trạng thái trước khi gọi function `delete_posts`:

[source,console,role="transcript"]
....
forumdb=> select pk,title from posts order by pk;
 pk |                title
----+------------------------------
   5 | Indexing PostgreSQL
   6 | Indexing Mysql
   7 | A view of     Data types in C++
(3 rows)
....

.SQL
[source,sql]
....
SELECT
    pk,
    title
FROM posts
ORDER BY pk;
....

.Output
[source,output]
....
 pk |                title
----+------------------------------
   5 | Indexing PostgreSQL
   6 | Indexing Mysql
   7 | A view of     Data types in C++
(3 rows)
....


Giả sử bây giờ muốn xóa row có column `title` bằng `A view of Data types in C++`. Table `posts` có column `pk` làm primary key; row `A view of Data types in C++` có `pk` bằng `7`. Vì vậy, trước hết hãy xóa các row trong table `j_posts_tags` có `post_pk=7`. Lý do là giữa hai table `posts` và `j_posts_tags` có một foreign key liên kết:

[source,console,role="transcript"]
....
     forumdb=> delete from j_posts_tags where post_pk = 7;
     DELETE 1
....

.SQL
[source,sql]
....
DELETE FROM j_posts_tags WHERE post_pk = 7;
....

.Output
[source,output]
....
     DELETE 1
....


Bây giờ hãy gọi function `delete_posts`, truyền `A view of Data types in C++` làm parameter. Đây là trạng thái sau khi gọi function `delete_posts`:

[source,console,role="transcript"]
....
     forumdb=> select delete_posts('A view of            Data types in C++');
      delete_posts
     --------------
                   7
     (1 row)
     forumdb=> select pk,title from posts order by pk;
      pk |          title
     ----+---------------------
       5 | Indexing PostgreSQL
       6 | Indexing Mysql
     (2 rows)
....

.SQL
[source,sql]
....
SELECT delete_posts('A view of            Data types in C++');
SELECT
    pk,
    title
FROM posts
ORDER BY pk;
....

.Output
[source,output]
....
      delete_posts
     --------------
                   7
     (1 row)
      pk |          title
     ----+---------------------
       5 | Indexing PostgreSQL
       6 | Indexing Mysql
     (2 rows)
....


Trong function này, chúng ta đã giới thiệu một data type mới: data type `setof`. Directive `setof` đơn giản là định nghĩa một result set gồm các giá trị thuộc một data type. Ví dụ, function `delete_posts` được định nghĩa để trả về một set integer, nên result của nó là một dataset integer. Có thể dùng directive `setof` với bất kỳ data type nào.

== SQL function trả về table

Ở phần trước, chúng ta đã thấy cách viết một function trả về result set chỉ gồm một data type; tuy nhiên, đôi khi function cần trả về result set gồm nhiều column. Hãy xét cùng function đó, nhưng lần này muốn trả về cặp `pk`, `title`, nên function sẽ như sau:

[source,console,role="transcript"]
....
     forumdb=> create or replace function delete_posts_table (p_title text)
     returns table (ret_key integer,ret_title text) AS $$
     delete from posts where title=p_title returning pk,title;
     $$
     language SQL;
     CREATE FUNCTION
....

[source,output]

== Polymorphic SQL function

Trong phần này, chúng ta sẽ giới thiệu ngắn gọn về polymorphic SQL function.

Polymorphic function hữu ích cho DBA khi cần viết một function hoạt động với nhiều data type khác nhau. Để hiểu rõ hơn, hãy bắt đầu bằng một ví dụ. Giả sử muốn tạo một thứ tương tự function Oracle `NVL`; nói cách khác, muốn tạo một function nhận hai parameter và dùng parameter thứ hai thay cho parameter thứ nhất nếu parameter thứ nhất là `NULL`. Vấn đề là cần một function duy nhất hợp lệ với mọi data type (integer, real, text, v.v.).

Function sau đây cho phép thực hiện điều đó:

[source,console,role="transcript"]
....
      forumdb=> create or replace function nvl ( anyelement,anyelement) returns
      anyelement as $$
      select coalesce($1,$2);
      $$
      language SQL;
      CREATE FUNCTION
....

.Command
[source,bash]
....
$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION nvl (anyelement, anyelement)
    returns
    anyelement AS $$
      select coalesce($1,$2);
....

.Output
[source,output]
....
      language SQL;
      CREATE FUNCTION
....


Đây là cách gọi function:

[source,console,role="transcript"]
....
      forumdb=> select nvl(NULL::int,1);
       nvl
      -----
           1
      (1 row)


      forumdb=> select nvl(''::text,'n'::text);
       nvl
      -----


      (1 row)

      forumdb=> select nvl('a'::text,'n'::text);
       nvl
      -----
       a
      (1 row)
....

.SQL
[source,sql]
....
SELECT nvl(NULL::int, 1);
SELECT nvl(''::text, 'n'::text);
SELECT nvl('a'::text, 'n'::text);
....

.Output
[source,output]
....
       nvl
      -----
           1
      (1 row)


       nvl
      -----


      (1 row)

       nvl
      -----
       a
      (1 row)
....


Để biết thêm thông tin, xem documentation chính thức tại https://www.postgresql.org/docs/current/extend-type-system.html.

== PL/pgSQL function

Trong phần này, chúng ta sẽ tìm hiểu về language PL/pgSQL. PL/pgSQL là procedural language được tích hợp sẵn trong PostgreSQL. Như được mô tả trong documentation chính thức, mục tiêu thiết kế của PL/pgSQL là tạo ra một procedural language có thể được nạp và có các khả năng sau:

* Được dùng để tạo function và trigger procedure (chúng ta sẽ tìm hiểu về trigger trong chương tiếp theo).
* Bổ sung các control structure mới.
* Bổ sung data type mới cho SQL language.

Nó rất giống Oracle PL/SQL và hỗ trợ các thành phần sau:

* Khai báo variable
* Expression
* Control structure như conditional structure hoặc loop structure
* Cursor

== Tổng quan đầu tiên

Như đã thấy ở đầu phần SQL function, prototype dùng để định nghĩa function trong PostgreSQL như sau:

[source,sql]
....
CREATE FUNCTION function_name(p1 type, p2 type, p3 type, ....., pn type)
    RETURNS type AS
BEGIN
    -- function logic
 END;
LANGUAGE language_name
....

Bây giờ, giả sử chúng ta muốn tạo lại function `my_sum` bằng language PL/pgSQL:

[source,console,role="transcript"]
....
   forumdb=> CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS
   integer AS
   $BODY$
   DECLARE
       ret integer;
   BEGIN
       ret := x + y;
       return ret;
      END;
      $BODY$
      language 'plpgsql';
      CREATE FUNCTION
   forumdb=> select my_sum(2,3);
    my_sum
   --------
          5
   (1 row)
....

.Command
[source,bash]
....
BODY$
BODY$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION my_sum(x integer, y integer)
    RETURNS
   integer AS
SELECT my_sum(2, 3);
....

.Output
[source,output]
....
   DECLARE
       ret integer;
   BEGIN
       ret := x + y;
       return ret;
      END;
      language 'plpgsql';
      CREATE FUNCTION
    my_sum
   --------
          5
   (1 row)
....


Query trên cho cùng result như query ở đầu chương. Bây giờ hãy xem xét chi tiết hơn:

. Đây là function header; tại đây, chúng ta định nghĩa tên function, input parameter và return value:

[source,sql]
....
CREATE OR REPLACE FUNCTION my_sum(x integer, y integer)
    RETURNS integer AS
....

. Đây là label đánh dấu phần bắt đầu của code. Có thể đặt bất kỳ string nào giữa các ký tự `$$`; điều quan trọng là label đó phải xuất hiện y hệt ở cuối function:

[source,console,role="transcript"]
....
       $BODY$
....

.Command
[source,bash]
....
BODY$
....


. Trong phần tiếp theo, chúng ta có thể định nghĩa các variable; điều quan trọng là mỗi declaration hoặc statement phải kết thúc bằng dấu chấm phẩy:

[source,text]
....
       DECLARE
         ret integer;
....

. Với statement `BEGIN`, chúng ta cho PostgreSQL biết rằng mình bắt đầu viết logic:

[source,sql]
....
BEGIN ret : = x + y;
return ret;
....

[CAUTION]
====
Không được viết dấu chấm phẩy sau `BEGIN`; điều đó không hợp lệ và sẽ gây ra syntax error.

====
[%start=5]
. Giữa statement `BEGIN` và statement `END`, chúng ta có thể đặt code:

[source,text]
....
            END;
....

. Statement `END` cho biết code đã kết thúc:

[source,console,role="transcript"]
....
            $BODY$
....

.Command
[source,bash]
....
BODY$
....


. Label này đóng label đầu tiên; cuối cùng, statement `language` chỉ định language dùng để viết function:

[source,text]
....
            language 'plpgsql';
....

== Drop function

Để drop một function, chúng ta phải thực thi command `DROP FUNCTION`, theo sau là tên function và các parameter của nó. Ví dụ, để drop function `my_sum`, hãy thực thi:

[source,console,role="transcript"]
....
   forumdb=> DROP FUNCTION my_sum(integer,integer);
   DROP FUNCTION
....

.SQL
[source,sql]
....
DROP FUNCTION my_sum(integer, integer);
....

.Output
[source,output]
....
   DROP FUNCTION
....


== Khai báo parameter của function

Sau khi đã biết cách viết một PL/pgSQL function đơn giản, hãy xem chi tiết hơn từng khía cạnh trong phần trước. Trước tiên là khai báo parameter. Hai ví dụ tiếp theo cho thấy hai cách khác nhau để định nghĩa function `my_sum` đã được trình bày trước đó.

Ví dụ đầu tiên như sau:

[source,console,role="transcript"]
....
   forumdb=> CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS
   integer AS
   $BODY$
   DECLARE
    x alias for $1;
    y alias for $2;
   ret integer;
   BEGIN
    ret := x + y;
    return ret;
   END;
   $BODY$
   language 'plpgsql';
   CREATE FUNCTION
....

.Command
[source,bash]
....
BODY$
BODY$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION my_sum(integer, integer)
    RETURNS
   integer AS
....

.Output
[source,output]
....
   DECLARE
    x alias for $1;
    y alias for $2;
   ret integer;
   BEGIN
    ret := x + y;
    return ret;
   END;
   language 'plpgsql';
   CREATE FUNCTION
....


Ví dụ thứ hai như sau:

[source,console,role="transcript"]
....
      forumdb=> CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS
      integer AS
      $BODY$
      DECLARE
       ret integer;

      END;

[source,bash]

BODY$

[source,sql]

    RETURNS
    integer AS

[source,output]

       ret := $1 + $2;

Trong ví dụ đầu tiên, chúng ta dùng alias; syntax tổng quát của alias như sau:

[source,text]
....
      newname ALIAS FOR oldname;
....

Trong trường hợp cụ thể này, positional variable `$1` được dùng làm giá trị `oldname`. Trong ví dụ thứ hai, chúng ta dùng cách tham chiếu theo vị trí, đúng như với SQL function.

== Parameter IN/OUT

Ở ví dụ trước, chúng ta dùng clause `RETURNS` ở dòng đầu tiên của function definition; tuy nhiên, có cách khác để đạt cùng mục tiêu. Trong PL/pgSQL, chúng ta có thể định nghĩa mỗi parameter là input parameter, output parameter hoặc input/output parameter. Ví dụ:

[source,console,role="transcript"]
....
      forumdb=> CREATE OR REPLACE FUNCTION my_sum_3_params(IN x integer,IN y
      integer, OUT z integer) AS
      $BODY$
      BEGIN
       z := x+y;
      END;
      $BODY$
      language 'plpgsql';
      CREATE FUNCTION
....

.Command
[source,bash]
....
BODY$
BODY$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION my_sum_3_params(IN x integer, IN y
    integer, OUT z integer) AS
....

.Output
[source,output]
....
      BEGIN
       z := x+y;
      END;
      language 'plpgsql';
      CREATE FUNCTION
....


Chúng ta đã định nghĩa một function mới có tên `my_sum_3_params`, nhận hai input parameter (`x` và `y`) và có output parameter `z`. Vì có hai input parameter nên function chỉ được gọi với hai parameter, giống hệt function trước:

[source,console,role="transcript"]
....
   forumdb=> select my_sum_3_params(2,3);
    my_sum_3_params
   -----------------
                     5
   (1 row)
....

.SQL
[source,sql]
....
SELECT my_sum_3_params(2, 3);
....

.Output
[source,output]
....
    my_sum_3_params
   -----------------
                     5

== Các category về volatility của function

Trong PostgreSQL, mỗi function có thể được định nghĩa là `VOLATILE`, `STABLE` hoặc `IMMUTABLE`. Nếu không chỉ định, giá trị mặc định là `VOLATILE`. Sự khác biệt giữa ba cách định nghĩa này được mô tả rõ trong documentation chính thức (https://www.postgresql.org/docs/current/xfunc-volatility.html):

[quote]
____
Một function `VOLATILE` có thể làm mọi việc, bao gồm sửa đổi database. Function này có thể trả về các result khác nhau trong những lần gọi liên tiếp với cùng các argument. Optimizer không đưa ra giả định nào về cách hoạt động của loại function này. Query sử dụng function volatile sẽ đánh giá lại function tại mỗi row cần giá trị của function. Nếu function được đánh dấu là `VOLATILE`, nó có thể trả về các result khác nhau khi được gọi nhiều lần với cùng các input parameter.

Một function `STABLE` không thể sửa đổi database và được đảm bảo trả về cùng result với cùng các argument cho mọi row trong một statement duy nhất. Category này cho phép optimizer tối ưu nhiều lần gọi function thành một lần gọi duy nhất. Cụ thể, sử dụng một expression chứa function như vậy trong index scan condition là an toàn. Nếu function được đánh dấu là `STABLE`, function sẽ trả về cùng result với cùng các parameter trong cùng một transaction.

Một function `IMMUTABLE` không thể sửa đổi database và được đảm bảo rằng, với cùng các argument, nó sẽ trả về cùng result mãi mãi. Category này cho phép optimizer pre-evaluate function khi query gọi function với các argument hằng số.

____
Trong các phần tiếp theo của chương, chúng ta chỉ tập trung vào các ví dụ về volatile function; tuy nhiên, trước hết hãy xem nhanh một ví dụ về stable function và một ví dụ về immutable function:

== IF statement

Trong PL/pgSQL, syntax của IF statement như sau:

[source,text]
....
   IF boolean-expression THEN
       statements
   [ ELSIF boolean-expression THEN
       statements
   [ ELSIF boolean-expression THEN
       statements
       ...
   ]
   ]
   [ ELSE
       statements ]
   END IF;
....

Ví dụ, giả sử muốn viết một function nhận hai input value `x` và `y`, rồi trả về các result sau:

* parameter thứ nhất lớn hơn parameter thứ hai khi `x > y`
* parameter thứ hai lớn hơn parameter thứ nhất khi `x < y`
* hai parameter bằng nhau khi `x = y`

   BEGIN
       IF x > y THEN
       return 'first parameter is greater than second parameter';
   ELSIF x < y THEN
       return 'second parameter is greater than first parameter';
       ELSE
       return 'the 2 parameters are equals';
       END IF;
   END;
   $BODY$
   language 'plpgsql';
   CREATE FUNCTION
....

== Loop statement

PL/pgSQL có thể xử lý loop theo nhiều cách. Tiếp theo, chúng ta sẽ xem một số ví dụ về cách tạo loop. Để biết thêm chi tiết, chúng tôi khuyến nghị tham khảo documentation chính thức tại https://www.postgresql.org/docs/current/plpgsql.html. PL/pgSQL đặc biệt hữu ích vì cho phép xử lý data từ các query bằng procedural language. Bây giờ hãy xem cách thực hiện điều đó.

Giả sử muốn xây dựng một PL/pgSQL function nhận một integer làm parameter và trả về một result set gồm các giá trị thuộc một composite data type. Composite data type cần trả về như sau:

[cols="3*", options="header"]
|===
|  |  | 
| ID | field pk | data type integer
| TITLE | field title | data type text
| RECORD_DATA | field title + field content | data type hstore
|===

Cách đúng để tạo một composite data type như sau:

[source,console,role="transcript"]
....
   forumdb=> create type my_ret_type as (
    id integer,
    title text,
    record_data hstore
   );
   CREATE TYPE
....

.SQL
[source,sql]
....
CREATE type my_ret_type AS (
    id integer,
    title text,
    record_data hstore
   );
....

.Output
[source,output]

....


Statement trên tạo một data type mới, cụ thể là một composite data type gồm các data type integer, text và hstore. Bây giờ, nếu muốn viết một function trả về một result set thuộc data type `my_ret_type`, lần thử đầu tiên có thể là:

[source,console,role="transcript"]
....
   forumdb=> CREATE OR REPLACE FUNCTION my_first_fun (p_id integer) returns
   setof my_ret_type as
   $$
   DECLARE
    rw posts%ROWTYPE; -- declare a rowtype;
    ret my_ret_type;
   BEGIN
         for rw in select * from posts where pk=p_id loop
           ret.id := rw.pk;
           ret.title := rw.title;
           ret.record_data := hstore(ARRAY['title',rw.title,'Title and Content'
                                   ,format('%s %s',rw.title,rw.content)]);
          return next ret;
          end loop;
      return;
   END;
   $$
   language 'plpgsql';
   CREATE FUNCTION
....

Như có thể thấy, đoạn code PL/pgSQL này chứa nhiều nội dung chỉ trong vài dòng:

. `rw posts%ROWTYPE`: Với statement này, biến `rw` được định nghĩa là container chứa một row duy nhất của table `posts`.
. `for rw in select * from posts where pk=p_id loop`: Với statement này, chúng ta lặp qua result của query; mỗi lần lặp, giá trị do query trả về được gán cho biến `rw`. Ba bước tiếp theo gán các giá trị cho biến `ret`.
. `return next ret;`: Statement này trả về giá trị của biến `ret` và chuyển sang record tiếp theo của vòng lặp for.
. `end loop;`: Statement này cho PostgreSQL biết rằng vòng lặp for kết thúc tại đây.
. `return;`: Đây là statement return của function.

[quote]
____
Điều quan trọng cần nhớ là PL/pgSQL chạy bên trong hệ thống transaction của PostgreSQL. Điều này có nghĩa là các function được thực thi atomically; function không trả về result tại thời điểm thực thi command `RETURN NEXT`, mà chỉ trả về khi thực thi command `RETURN` ở cuối function. Với dataset rất lớn, điều này có thể khiến PL/pgSQL function mất nhiều thời gian trước khi trả về result.

____

== Các statement xử lý exception

PL/pgSQL cũng có thể xử lý exception. Block `BEGIN...END` của function cho phép dùng option `EXCEPTION`, hoạt động như một catch block. Ví dụ, khi viết function chia hai số, chúng ta có thể gặp vấn đề nếu chia cho 0:

[source,console,role="transcript"]
....
forumdb=> CREATE OR REPLACE FUNCTION my_first_except (x real, y real )
returns real as
$$
DECLARE
   ret real;
BEGIN
   ret := x / y;
   return ret;
END;
$$
language 'plpgsql';
CREATE FUNCTION
....

.Command
[source,bash]
....
$
$
....

.SQL
[source,sql]
....
CREATE OR REPLACE FUNCTION my_first_except (x real, y real)
    returns real AS
....

.Output
[source,output]
....
DECLARE
   ret real;
BEGIN
   ret := x / y;
   return ret;
END;
language 'plpgsql';
CREATE FUNCTION
....


Function này hoạt động tốt khi `y <> 0`, như minh họa dưới đây:

[source,console,role="transcript"]
....
forumdb=> \x
Expanded display is off.
forumdb=> select my_first_except(4,2);
   my_first_except
-----------------
                  2
(1 row)
....

.SQL
[source,sql]
....

....

.Output
[source,output]
....

   my_first_except
-----------------
                  2
(1 row)
....


Tuy nhiên, nếu `y` bằng 0, chúng ta sẽ gặp vấn đề:

[source,console,role="transcript"]
....
forumdb=> select my_first_except(4,0);

CONTEXT: PL/pgSQL function my_first_except(real,real) line 5 at
assignment
....

.SQL
[source,sql]

SELECT my_first_except(4, 0);
....

.Output
[source,output]
....

CONTEXT: PL/pgSQL function my_first_except(real,real) line 5 at
assignment
....


Để giải quyết vấn đề này, chúng ta phải xử lý exception. Để làm vậy, hãy viết lại function như sau:

[source,console,role="transcript"]
....
forumdb=> CREATE OR REPLACE FUNCTION my_second_except (x real, y real )
returns real as
$$
DECLARE
   ret real;
BEGIN
   ret := x / y;
   return ret;
EXCEPTION
   WHEN division_by_zero THEN
         RAISE INFO 'DIVISION BY ZERO';
         RAISE INFO 'Error % %', SQLSTATE, SQLERRM;
         RETURN 0;
END;
$$
language 'plpgsql' ;
CREATE FUNCTION
....

[source,bash]
....

$
....

== Security definer

Option này cho phép user gọi một function như thể user đó là owner của function. Nó có thể hữu ích khi muốn hiển thị data mà user thông thường không có quyền truy cập.

Ví dụ, PostgreSQL có một system view tên là `pg_stat_activity`, cho phép xem PostgreSQL hiện đang làm gì.

Với user forum, hãy thực thi statement sau:

[source,console,role="transcript"]
....
postgres@learn_postgresql:~$ psql -U forum forumdb
forumdb=>

forumdb=> select pid,query from pg_stat_activity          ;
   pid |                       query
-----+------------------------------------------
    74 | <insufficient privilege>
    75 | <insufficient privilege>
   217 | select pid,query from pg_stat_activity ;
   [..]
....

.Command
[source,bash]
....
psql -U forum forumdb
....

.SQL
[source,sql]
....
SELECT
    pid,
    query
FROM pg_stat_activity;
....

.Output
[source,output]
....
   pid |                       query
-----+------------------------------------------
    74 | <insufficient privilege>
    75 | <insufficient privilege>
   217 | select pid,query from pg_stat_activity ;
   [..]
....


Như có thể thấy, một số result là `<insufficient privilege>`. Có thể giải quyết vấn đề này theo các bước sau:

* Kết nối tới database bằng user postgres:

[source,console,role="transcript"]
....
  postgres@learn_postgresql:~$ psql forumdb
  forumdb=#
....

.Command
[source,bash]
....
psql forumdb
....


* Bây giờ hãy thực thi function `my_stat_activity()` được định nghĩa dưới đây:

[source,console,role="transcript"]
....
  forumdb=# create function forum.my_stat_activity()
  returns table (pid integer,query text)
  as $$
          select pid, query   from pg_stat_activity;
  $$ language 'sql'
  security definer;
....

.Command
[source,bash]
....
$ language 'sql'
....

.SQL
[source,sql]
....
CREATE FUNCTION forum.my_stat_activity()
    returns TABLE (pid integer, query text)
  AS $$
          select pid, query   from pg_stat_activity;
....

.Output
[source,output]
....
  security definer;
....


* Cấp quyền EXECUTE trên function `forum.my_stat_activity` cho user forum. Chúng ta sẽ tìm hiểu tính năng này trong Chapter 10, Granting and Revoking Permissions:

[source,console,role="transcript"]
....
  forumdb=# grant execute on function forum.my_stat_activity TO forum;
....

.SQL
[source,sql]
....
GRANT execute ON FUNCTION forum.my_stat_activity TO forum;
....


* Kết nối lại tới database bằng user forum:

[source,console,role="transcript"]
....
  postgres@learn_postgresql:~$ psql -U forum forumdb
  forumdb=>
....

.Command
[source,bash]
....
psql -U forum forumdb
....


* Bây giờ hãy thực thi query sau:

[source,console,role="transcript"]
....
  forumdb=> select * from my_stat_activity();
   pid |                 query
  -----+-----------------------------------
     74 |
     75 |
    271 | select * from my_stat_activity();
    [..]
....

.SQL
[source,sql]
....
SELECT *
FROM my_stat_activity();
....

.Output
[source,output]
....
   pid |                 query
  -----+-----------------------------------
     74 |
     75 |
    271 | select * from my_stat_activity();
    [..]
....


Vấn đề trước đó không còn xảy ra. Đó là vì security definer cho phép function `forum.my_stat_activity()` được thực thi với quyền của user đã tạo function; trong trường hợp này, user tạo function là user postgres.
