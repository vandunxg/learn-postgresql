= Khám phá cách thiết lập logical replication và các tính năng mới của logical replication trên PostgreSQL 16

Bây giờ hãy khám phá cách thực hiện logical replication. Trong phần này, chúng ta sẽ chuẩn bị môi trường cần thiết để có thể thực hiện logical replication.

== Thiết lập môi trường logical replication

Giả sử chúng ta có hai server, gọi là `pg_pub` và `pg_sub`. Hãy nhớ thiết lập DNS nội bộ hoặc file `/etc hosts` để `pg_pub` có thể kết nối tới `pg_sub`; ví dụ, trên server `pg_pub`, primary server có IP `192.168.144.3`, còn trên server `pg_sub`, replica server có IP `192.168.144.2`. Nếu sử dụng container `chapter18`, bạn có thể chạy:

[source,text]
....
chapter_18$ bash run-pg-docker.sh chapter18_logical_clear
....

Sau khi vào container đầu tiên, bạn có thể mở một terminal Bash khác và chạy:

[source,text]
....
chapter_18$ bash run-pg-docker_replica.sh chapter18_logical_clear
....

Bây giờ hãy kiểm tra xem hai server có kết nối với nhau hay không:

[source,console,role="transcript"]
....
postgres@pg_pub:~$ ping pg_sub

64 bytes from chapter18_logical_clear_learn_postgresql_pub_1.chapter18_
logical_clear_default (192.168.144.2): icmp_seq=1 ttl=64 time=0.070 ms
....

.Command
[source,bash]

ping pg_sub

== Role dành cho replication

Để thực hiện logical replication, cũng như trong chương trước về physical replication, chúng ta cần một database user có quyền replication. Vì vậy, hãy tạo user sau trên publication server:

[source,console,role="transcript"]
....
postgres=# CREATE USER replicarole WITH REPLICATION ENCRYPTED PASSWORD
'LearnPostgreSQL';
CREATE ROLE
....

.SQL
[source,sql]
....
CREATE USER replicarole WITH REPLICATION ENCRYPTED PASSWORD
'LearnPostgreSQL';
....

.Output
[source,output]
....
CREATE ROLE
....


User này sẽ được dùng để quản lý logical replication.

== Primary server – postgresql.conf

Bây giờ chúng ta sẽ sửa file `postgresql.conf` trên cả hai server để bảo đảm cả hai server đều listen trên port 5432 ở mọi network interface. Sau đó, chúng ta sẽ sửa thêm một số giá trị để cố gắng tối ưu hóa quy trình logical replication:

. Trước tiên, thêm các dòng sau vào cuối file `postgresql.conf` trên publication server:

[source,console,role="transcript"]
....
   # Add settings for extensions here
   listen_addresses = '*'
   wal_level = logical
   max_wal_senders = 10
....

.Command
[source,bash]
....
Add settings for extensions here
....

.Output
[source,output]
....
   listen_addresses = '*'
   wal_level = logical
   max_wal_senders = 10
....


Bây giờ hãy xem lần lượt từng parameter:

* `listen addresses = '*'`: Theo cách này, PostgreSQL sẽ listen trên port 5432 ở tất cả network interface. Chúng ta cũng chỉ cần thêm địa chỉ IP của interface mà dịch vụ PostgreSQL cần listen.
* `wal level = logical`: Chúng ta đã đổi giá trị từ `replica` (mặc định) thành `logical`; theo cách này, ngoài toàn bộ thông tin có trong thiết lập `wal level = replica`, PostgreSQL sẽ bổ sung thông tin để có thể thực hiện quá trình reverse engineering. Với `wal level = logical`, chúng ta bật khả năng logical replication.
* `max_replication_slots = 10`: Giá trị này phải được đặt thành ít nhất một cho mỗi subscriber, cộng thêm số slot cần thiết để khởi tạo các table.
* `max_wal_senders = 10`: Giá trị này phải được đặt tối thiểu bằng số lượng replication slot, cộng thêm số cần thiết cho physical replication.
[%start=2]
. Sau khi đặt các giá trị này, hãy restart PostgreSQL trên primary server bằng cách thực thi:

[source,console,role="transcript"]
....
# systemctl restart postgresql
....

.Command
[source,bash]
....
systemctl restart postgresql
....


Với container đi kèm sách, chúng ta chỉ cần thoát khỏi container bằng `Ctrl + D`, rồi restart container đó.

== Replica server – postgresql.conf

Đối với replica server, các thay đổi trong `postgresql.conf` như sau:

[source,console,role="transcript"]
....
# Add settings for extensions here
max_logical_replication_workers = 4
max_worker_processes = 10
....

.Command
[source,bash]
....
Add settings for extensions here
....

.Output
[source,output]
....
max_logical_replication_workers = 4
max_worker_processes = 10
....


Như có thể thấy, các giá trị của `listen_addresses` và `wal_level` giống hệt như trên primary server; ở đây không có giá trị cho `max_replication_slots` và `max_wal_senders`, nhưng có các giá trị sau:

* `max_logical_replication_workers`: Parameter này phải được đặt thành một cho mỗi subscription, cộng thêm một số giá trị cần thiết cho việc đồng bộ table.
* `max_worker_processes`: Giá trị này phải được đặt tối thiểu bằng một cho mỗi replication worker, cộng thêm một.

Ở đây, cũng như với primary, hãy restart PostgreSQL server:

[source,console,role="transcript"]
....
# systemctl restart postgresql
....

.Command
[source,bash]
....
systemctl restart postgresql
....

[source,console,role="transcript"]

....


Điều này cho phép user trên replica server thực hiện replication và query primary server. Để kích hoạt các thay đổi, cần reload primary server:

== Thiết lập logical replication

Đến đây, chúng ta đã sẵn sàng bắt đầu chuẩn bị logical replica:

. Hãy chuyển sang primary server và tạo database:

[source,console,role="transcript"]
....
   postgres=# create database db_source;
   CREATE DATABASE
   dostgres=# \c db_source
   You are now connected to database "db_source" as user "postgres"
....

.SQL
[source,sql]
....

\c db_source
....

.Output
[source,output]

   You are now connected to database "db_source" as user "postgres"
....


. Bây giờ hãy tạo table tên là `t1` và bảo đảm table có primary key:

[source,console,role="transcript"]
....
   db_source=# create table t1 (id integer not null primary key, name
   varchar(64));
   CREATE TABLE
....

[source,sql]

. Hãy cấp quyền SELECT cho user `REPLICAROLE`:

[source,console,role="transcript"]

   replicarole;
   GRANT
....

.SQL
[source,sql]

GRANT SELECT ON ALL TABLES IN SCHEMA public TO
   replicarole;

.Output
[source,output]

. Bây giờ hãy tạo publication trên primary server và chỉ ra danh sách các table muốn replicate trên replica server.

== Read-only và cho phép ghi

Trong chương trước, chúng ta đã thấy rằng chỉ có thể truy cập physical replication server bằng thao tác đọc và không thể thực hiện thao tác ghi. Chúng ta cũng đã thấy physical replication replicate mọi loại thao tác, cả thao tác DML và thao tác DDL. Với logical replication, chúng ta cũng có thể thực hiện thao tác ghi trên replica server; tuy nhiên, ở logical replica, chỉ thao tác DML được replicate tới replica server, còn thao tác DDL thì không. Hãy thực hiện một số kiểm tra để xem điều gì xảy ra. Trong các ví dụ sau, primary server luôn được gọi là `pg_pub`, còn server có logical replication luôn được gọi là `pg_sub`.

(2 rows)

== Vô hiệu hóa logical replication

Ở phần trước, chúng ta đã dùng lệnh `DROP SUBSCRIPTION` để xóa một subscription. Có thể có những trường hợp không thể trực tiếp dùng lệnh này. Ví dụ, giả sử không thể truy cập primary server và chúng ta cần xóa subscription trên replica server. Nếu thử thực thi lệnh `DROP SUBSCRIPTION`, chúng ta sẽ nhận được phản hồi sau:

[source,console,role="transcript"]
....
db_destination=# drop subscription sub_all_tables ;
ERROR:     could not connect to publisher when attempting to [..]
HINT: Use ALTER SUBSCRIPTION ... SET (slot_name = NONE) to disassociate
the subscription from the slot.
....

.SQL
[source,sql]
....
DROP subscription sub_all_tables;
....

.Output
[source,output]
....
ERROR:     could not connect to publisher when attempting to [..]
HINT: Use ALTER SUBSCRIPTION ... SET (slot_name = NONE) to disassociate
the subscription from the slot.
....


PostgreSQL đề xuất dùng `ALTER SUBSCRIPTION ... SET (slot_name = NONE)` để tách subscription khỏi slot. Vấn đề là chúng ta không thể thực thi lệnh này trước khi vô hiệu hóa subscription. Thực tế, nếu thử thực hiện lệnh PostgreSQL đề xuất ngay bây giờ, chúng ta sẽ nhận được:

[source,console,role="transcript"]
....
db_destination=#     alter subscription sub_all_tables SET (slot_name =
NONE);
ERROR:    cannot set slot_name = NONE for enabled subscription
....

.SQL
[source,sql]
....
ALTER subscription sub_all_tables SET (slot_name =
NONE);
....

.Output
[source,output]
....
ERROR:    cannot set slot_name = NONE for enabled subscription
....


Các bước đúng cần thực hiện như sau:

. Vô hiệu hóa subscription.
. Đặt `slot_name` thành `NONE`.
. Xóa subscription.

Chúng ta phải thực hiện ba statement sau:

[source,console,role="transcript"]
....
db_destination=# alter subscription sub_all_tables disable;
ALTER SUBSCRIPTION
db_destination=# alter subscription sub_all_tables SET (slot_name = NONE);
ALTER SUBSCRIPTION
db_destination=# drop subscription sub_all_tables ;
DROP SUBSCRIPTION
....

.SQL
[source,sql]
....
ALTER subscription sub_all_tables disable;
ALTER subscription sub_all_tables SET (slot_name = NONE);
DROP subscription sub_all_tables;
....

.Output
[source,output]
....
ALTER SUBSCRIPTION
ALTER SUBSCRIPTION
DROP SUBSCRIPTION
....


Đây là các bước đúng nếu muốn xóa một subscription khi không thể truy cập primary server. Ta cũng có thể dùng lệnh `ALTER SUBSCRIPTION sub_name DISABLE` để tách subscription khỏi publication và lệnh `ALTER SUBSCRIPTION sub_name ENABLE` để gắn lại subscription vào publication.

== Tạo logical replication từ một instance đang chạy physical replication

Trên PostgreSQL 16, có thể tạo logical replication bắt đầu từ một physical replication.

Các bước cần thực hiện là:

. Đặt `wal_level=logical` trên primary server và physical replication server.

   Trên primary server:

[%start=2]
. Tạo một role cho physical replication:

[source,sql]
....
CREATE ROLE replicarole WITH REPLICATION LOGIN PASSWORD 'LearnPostgreSQL'.
....

. Tạo một role cho logical replication trên primary server:

[source,sql]
....
CREATE ROLE logicalreplicarole WITH REPLICATION LOGIN PASSWORD 'LearnPostgreSQL'
....

. Gán các quyền phù hợp cho `logicalreplicarole` trên các schema và table mà chúng ta muốn replicate bằng logical replication, chẳng hạn:

[source,sql]
....
GRANT USAGE ON SCHEMA forum TO logicalreplicarole;
GRANT SELECT ON forum.users TO logicalreplicarole
....

. Tạo một physical replication slot hoặc physical replication.

. Tạo một publication sẽ được replicate trên physical replication server và được subscription của logical replication server sử dụng.

   Trên physical replication server:

[%start=7]
. Đặt `hot_standby_feedback = on` để ngăn các vấn đề do hoạt động vacuum trên primary server gây ra và phản ánh trên replica server; các vấn đề này có thể gây xung đột với những query rất dài trên replica.

. Tạo replica bằng lệnh `pg_basebackup`, như đã mô tả trong chương trước.

   Trên logical replication server:

[%start=9]
. Tạo các table mà bạn muốn nhận dữ liệu được replicate từ physical replication server.

. Tạo một subscription tham chiếu tới publication được tạo trên primary, như đã trình bày.

Bây giờ, hãy thử tính năng này bằng Docker container; kịch bản cần thử là:

[%start=11]
. Một database `forumdb` trên primary server.
. Một physical replica của toàn bộ cluster trên replica server.
. Một logical replication cho các table `forum.users` trên logical replication server.
