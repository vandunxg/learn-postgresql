= Trích xuất thông tin từ log – pgBadger

Vì log có thể chứa rất nhiều thông tin, việc phân tích và trích xuất thông tin từ log có thể được tự động hóa. Có một số công cụ phục vụ mục đích này, và pgBadger là một trong những công cụ phổ biến và toàn diện nhất.

pgBadger là một ứng dụng Perl 5 độc lập, đọc PostgreSQL log và cẩn thận trích xuất thông tin từ đó, sau đó tạo một web dashboard tóm tắt toàn bộ thông tin tìm thấy. Mục đích của ứng dụng này là giúp bạn khai thác log hiệu quả hơn mà không cần tự tìm thủ công từng thông tin cụ thể.

Bạn không bắt buộc phải sử dụng pgBadger; cluster vẫn hoạt động bình thường khi không có pgBadger, và bạn vẫn có thể tìm thấy thông tin cũng như các vấn đề trong log. Tuy nhiên, pgBadger cung cấp cho bạn những gợi ý hữu ích hơn về những gì server đã thực hiện.

Điều quan trọng cần lưu ý là pgBadger, cũng như mọi hình thức phân tích log tự động hoặc thủ công, không cung cấp thông tin theo thời gian thực mà chỉ cho thấy hoạt động trong quá khứ của server.

Trong các tiểu mục tiếp theo, bạn sẽ học cách cài đặt và sử dụng pgBadger.

== Cài đặt pgBadger

pgBadger yêu cầu Perl 5 được cài đặt trên hệ thống nơi nó chạy; đó là dependency duy nhất của pgBadger. Bạn có thể chạy pgBadger trên cùng host với PostgreSQL cluster hoặc trên một hệ thống từ xa (như sẽ trình bày trong một tiểu mục sau). Trong phần này, chúng ta giả định pgBadger được cài đặt và thực thi ngay trên máy đang chạy PostgreSQL cluster.

Cách dễ nhất để cài đặt pgBadger là dùng package manager của operating system, chẳng hạn như trên các hệ thống dựa trên GNU/Debian và Ubuntu:

[source,console,role="transcript"]
....
      $ sudo apt install pgbadger
....

.Command
[source,bash]
....
sudo apt install pgbadger
....


Bạn cũng có thể cài đặt pgBadger từ source bằng các bước sau:

[source,console,role="transcript"]

   $ tar xzvf v12.0.tar.gz
   $ cd pgbadger-12.0
   $ perl Makefile.PL
   $ make
   $ sudo make install
....

== Cấu hình logging của PostgreSQL để sử dụng pgBadger

pgBadger đủ thông minh để hiểu PostgreSQL log trong nhiều trường hợp, nhưng trong một số tình huống, bạn cần chỉ định một vài option cấu hình để PostgreSQL tạo ra log dễ hiểu hơn.

Trước hết, pgBadger cần truy cập được PostgreSQL log, vì vậy bạn nên sử dụng `logging_collector` để tạo log. Nếu thay đổi `log_line_prefix`, bạn nên truyền setting đó cho pgBadger để nó có thể parse chính xác log prefix. Cuối cùng, bạn nên bật càng nhiều logging context càng tốt.

Sau đây là ví dụ về các configuration parameter giúp PostgreSQL tạo ra log mà pgBadger có thể parse chính xác:

[source,text]
....
   logging_collector = on
   log_destination       = 'stderr,csvlog,jsonlog'
   log_directory         = 'log'
   log_filename          = 'postgresql-%Y-%m-%d.log'
   log_rotation_age      = '1d'
   log_rotation_size = '50MB'

       log_min_duration_statement = 500
       log_min_duration_sample = 100
       log_statement_sample_rate = 0.8
       log_transaction_sample_rate = 0.5

       log_min_duration_statement = 0
....

[quote]
____
pgBadger đã được cài đặt sẵn trong Docker image đi kèm chương này.

____
Sau khi server đã được cấu hình để áp dụng cấu hình logging mới, bạn có thể bắt đầu sử dụng pgBadger.

== Sử dụng pgBadger

Khi PostgreSQL bắt đầu tạo log, bạn có thể dùng pgBadger để phân tích kết quả. Trước khi chạy pgBadger, đặc biệt trên hệ thống test, bạn nên tạo (hoặc chờ) một lượng traffic và statement (cũng như transaction); nếu không, dashboard được tạo sẽ rỗng.

Trước khi bắt đầu sử dụng pgBadger, bạn nên tạo một directory để lưu report và các thành phần liên quan. Việc này không bắt buộc, nhưng sẽ đơn giản hóa việc maintenance và archiving report về sau, khi bạn cần lưu giữ chúng. Hãy tạo một directory và gán ownership của directory đó cho Postgres user đang chạy cluster (một lần nữa, việc này không bắt buộc nhưng sẽ giúp workflow đơn giản hơn một chút):

[source,console,role="transcript"]
....
      $ sudo mkdir /data/html
      $ sudo chown postgres:www-data /data/html
....

.Command
[source,bash]
....
sudo mkdir /data/html
sudo chown postgres:www-data /data/html
....


Bây giờ hãy khởi chạy pgBadger lần đầu:

[source,console,role="transcript"]
....
   $ pgbadger -o /data/html/first_report.html \
                   /postgres/16/data/log/postgresql
   -2023-07-19.log
   [========================>] Parsed 261891612 bytes of 261891612 (100.00%),
   queries: 1428472, events: 2
   7
   LOG: Ok, generating html report...
....

.Command
[source,bash]
....
pgbadger -o /data/html/first_report.html \
....

.Output
[source,output]
....
                   /postgres/16/data/log/postgresql
   -2023-07-19.log
   [========================>] Parsed 261891612 bytes of 261891612 (100.00%),
   queries: 1428472, events: 2
   7
   LOG: Ok, generating html report...
....


Đối số đầu tiên, `-o`, chỉ định tên file dùng để lưu report. pgBadger tạo đúng một file cho mỗi lần chạy, vì vậy bạn cần đổi tên file nếu muốn tạo report khác mà không ghi đè lên report hiện có.

Đối số thứ hai là PostgreSQL log file cần phân tích; bạn cũng có thể chỉ định file JSON hoặc CSV, và pgBadger sẽ parse chúng tương ứng.

Chương trình chạy trong vài giây hoặc vài phút, tùy thuộc vào kích thước log file, đồng thời báo cáo một số thống kê về những gì nó tìm thấy trong log file (trong ví dụ này là 1,4 triệu statement). Bạn có thể dễ dàng kiểm tra file report được tạo:

== Lập lịch pgBadger

pgBadger có thể được chạy theo lịch để liên tục tạo các report chính xác trong một khoảng thời gian xác định. Điều này khả thi nhờ tính năng incremental của pgBadger; report sẽ không bị ghi đè sau mỗi lần chạy, mà thay vào đó, chương trình có thể tạo report theo từng giờ và một report tổng hợp theo từng tuần.

Điều này hữu ích vì bạn có thể, chẳng hạn, lập lịch chạy pgBadger bằng `cron(1)` rồi không cần can thiệp thêm. Trước tiên, hãy xem cách chạy pgBadger trong incremental mode:

[source,console,role="transcript"]
....
      $ pgbadger -I --outdir /data/html -f stderr            /postgres/16/data/log/
      postgresql-2023-*.log
      [========================>] Parsed 22008130 bytes of 22008130 (100.00%),
      queries: 120569, events: 1
      LOG: Ok, generating HTML daily report into /data/html/2023/07/19/...
      LOG: Ok, generating HTML weekly report into /data/html/2023/week-30/...
      LOG: Ok, generating global index to access incremental reports...
....

.Command
[source,bash]
....
pgbadger -I --outdir /data/html -f stderr            /postgres/16/data/log/
....

.Output
[source,output]
....
      postgresql-2023-*.log
      [========================>] Parsed 22008130 bytes of 22008130 (100.00%),
      queries: 120569, events: 1
      LOG: Ok, generating HTML daily report into /data/html/2023/07/19/...
      LOG: Ok, generating HTML weekly report into /data/html/2023/week-30/...
      LOG: Ok, generating global index to access incremental reports...
....


Đối số `-I` chỉ định incremental mode, vì vậy pgBadger sẽ tạo các file riêng cho report theo giờ và theo tuần. Lưu ý rằng thay vì chỉ định output file, option `--outdir` được dùng để chỉ định directory chứa các file đó. Option `-f` cho pgBadger biết loại log mà nó đang xử lý; trong ví dụ này là các text file thông thường. Cuối cùng, như thường lệ, log file cần phân tích được biểu diễn dưới dạng shell glob (`postgresql-2023-*.log`).

Kết quả cuối cùng, như bạn có thể đoán từ output của chương trình, là một directory tree có dạng tương tự như sau:

[source,console,role="transcript"]
....
       $ ls -R /data/html/
      /data/html/:
      2023   LAST_PARSED   index.html


      /data/html/2023:
      07   week-30


      /data/html/2023/07:
      19


      /data/html/2023/07/19:
      2023-07-19-65.bin    index.html

      /data/html/2023/week-30:
      index.html
....

.Command
[source,bash]
....
ls -R /data/html/
....

.Output
[source,output]
....
      /data/html/:
      2023   LAST_PARSED   index.html


      /data/html/2023:
      07   week-30


      /data/html/2023/07:
      19


      /data/html/2023/07/19:
      2023-07-19-65.bin    index.html

      /data/html/2023/week-30:
      index.html
....


File `index.html` chính là entry point của toàn bộ incremental report. Tiếp theo là một tree gồm các directory tương ứng với năm (2023), tháng (07) và ngày (19), cùng một file `index.html` cho ngày đó.

Ngoài ra, một phần của tree được dùng để tập hợp dữ liệu cho tuần hiện tại; trong trường hợp này là tuần số 30. Vì vậy, tree sẽ được mở rộng khi có thêm ngày mới. pgBadger dùng file đặc biệt `LAST_PARSED` để ghi nhớ đã dừng parse ở đâu, nhờ đó có thể bắt đầu từ vị trí đó trong lần gọi incremental tiếp theo.

Nếu trỏ web browser tới file index chính, bạn sẽ thấy một calendar như trong screenshot sau, nơi bạn có thể chọn tháng và ngày để xem report theo từng ngày.

*Hình 14.6: Global dashboard của pgBadger trong một khoảng ngày*

Khi click vào một ngày cụ thể, bạn sẽ được chuyển tới daily report, nơi hiển thị đúng các dashboard đã thảo luận trước đó. Rõ ràng, bạn không thể click vào những ngày chưa có report hoặc không có activity tương ứng trong PostgreSQL log.

Nhờ cách tiếp cận incremental, giờ đây bạn có thể lập lịch chạy bằng scheduler của riêng mình; ví dụ, trong `cron(1)`, bạn có thể thêm một dòng như sau:

[source,text]
....
   59 23 * * * pgbadger -I --outdir /data/html/ -f stderr /postgres/16/data/
   log/postgresql-'date +'%Y-%m-%d''.log
....

Về cơ bản, đây là command line giống lệnh trước đó, chỉ khác ở chỗ ngày hiện tại được tự động tính. Lệnh này sẽ tạo report cho ngày hiện tại vào cuối mỗi ngày, rồi dùng report đó để populate report tree.

[quote]
____
Entry trước đó trong crontab chỉ là một ví dụ. Hãy cân nhắc bọc toàn bộ logic trong một script robust và kiểm tra việc thực thi script có chính xác hay không.

____
Cuối cùng, bạn có thể chạy pgBadger từ một remote host, nhờ đó dành riêng một máy để thu thập tất cả report và thông tin tại một nơi. Trên thực tế, pgBadger chấp nhận một URI parameter trỏ tới log directory (hoặc file) ở remote location và có thể truy cập vị trí đó qua FTP hoặc SSH; SSH an toàn hơn và được khuyến nghị.

Ví dụ sau sử dụng command line giống như trước, nhưng lần này pgBadger lấy log trong incremental mode từ một PostgreSQL host từ xa có tên `miguel`:

[source,console,role="transcript"]
....
   $ pgbadger -I --outdir /data/html ssh://postgres@miguel//postgres/16/
   data/log/postgresql-'date +'%Y-%m-%d''.pgbadger.log
   [========================>] Parsed 313252 bytes of 313252 (100.00%),
   queries: 841, events: 34
....

.Command
[source,bash]
....
pgbadger -I --outdir /data/html ssh://postgres@miguel//postgres/16/
....

.Output
[source,output]
....
   data/log/postgresql-'date +'%Y-%m-%d''.pgbadger.log
   [========================>] Parsed 313252 bytes of 313252 (100.00%),
   queries: 841, events: 34
....


Lưu ý rằng log file được chỉ định thông qua SSH URL. Khuyến nghị mạnh mẽ rằng bạn nên sử dụng một user trên máy từ xa có quyền truy cập log và thực hiện SSH key exchange để tự động hóa việc đăng nhập giữa các host.

Bây giờ chúng ta đã biết cách sử dụng log, hãy chuyển sang một cách tiếp cận khác cho nhiệm vụ này: auditing.
